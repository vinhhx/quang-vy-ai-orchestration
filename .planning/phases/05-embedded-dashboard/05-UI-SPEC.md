# Phase 5 — UI Design Contract

> Visual and interaction contract for the embedded dashboard (`agent-brain serve`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> There is no Figma design and no component library (D-18, DASH-10 not applicable). The contract below is the only visual source of truth for the executor and for the end-of-phase UAT (plan 05-13).

**Sources.** Locked: CONTEXT D-15..D-23 (profile switcher, language, style, theme, log pane, stepper). Stack: RESEARCH (Tailwind v4.3.3 standalone CLI with a committed `app.css`, Alpine.js CSP build 3.17.4, CSP `script-src 'self'; style-src 'self'`, nothing from a CDN). Structure and class conventions: plans 05-08 (shell, Tổng quan), 05-09 (Giao việc), 05-10 (Chi tiết task), 05-11 (Thống kê, Dự án). Where this file differs from those plans it says so in `## Deltas vs existing plans`. Choices CONTEXT does not decide are marked `[ASSUMED Un]` and listed in `## Assumptions`.

**Hard constraints that shape every rule below**
- Offline: no web fonts, no icon fonts, no external images. System font stack only.
- `app.css` is generated by Tailwind from the class names it finds as full strings in `assets/dashboard/**`; `dashboard-src/input.css` is test-asserted to be exactly three lines, so **this contract uses only Tailwind's default theme** (default palette, default font stacks, default spacing). No `@theme` block.
- Strict CSP: no inline `<script>`, no `style="..."` attribute, no `x-html`. Dynamic widths/heights go through `:style` bound to a method that returns an object (applied through `element.style`, which the CSP allows).
- Alpine CSP build: no arrow functions, template literals, negation, ternaries or globals in templates; logic lives in `Alpine.data`.
- Interface text is Vietnamese (D-19). Technical terms stay English: task, run, token, Kill, Lead / Dev / QA, profile, work / personal, branch, commit, plan, log.

## Spacing Scale

Declared values (all multiples of 4; Tailwind step in brackets):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`1`) | Gap between a glyph and its label, log-row vertical padding, chip gaps |
| sm | 8px (`2`) | Compact gaps, button vertical padding, table cell vertical padding |
| md | 16px (`4`) | Default gap between controls, button/input horizontal padding, stepper card gap |
| lg | 24px (`6`) | Card padding, gap between cards (`gap-6`, `space-y-6`), page horizontal padding |
| xl | 32px (`8`) | Page vertical padding (`py-8`), gap between major blocks inside a card |
| 2xl | 48px (`12`) | Empty-state vertical padding |
| 3xl | 64px (`16`) | Not used on any screen in this phase; reserved |

Exceptions (explicit, nothing else is allowed):
- **12px (`3`)**: horizontal padding and gap inside compact pills/badges and log rows (`px-3`, `gap-3`). It is a multiple of 4 but sits between sm and md.
- **40px minimum control height** (`min-h-10`): buttons, inputs, selects, list options (touch/click target comfort).
- **1px / 2px**: hairline `ring-1` borders and the 2px focus outline. These are not spacing.
- Container: `max-w-6xl mx-auto px-6 py-8` (1152px max).

Layout rules
- Page rhythm `space-y-6`; card internal rhythm `space-y-4` (16px) between label/control groups, `space-y-6` between sections of a long card.
- Breakpoints (Tailwind defaults): `md` = 768px, `lg` = 1024px. Below `md` everything stacks to one column.
- Header: `flex flex-wrap items-center gap-4`; it wraps instead of overflowing.

## Typography

Exactly four sizes and two weights (400 and 600). No other size or weight class may appear in the dashboard files (`text-xs`, `font-medium`, `font-bold`, `text-3xl` etc. are forbidden).

| Role | Size | Weight | Line Height | Tailwind | Used for |
|------|------|--------|-------------|----------|----------|
| Body | 16px | 400 | 1.5 | `text-base font-normal leading-normal` | Paragraphs, input text, plan and QA section text |
| Label | 14px | 600 | 1.5 | `text-sm font-semibold leading-normal` | Field labels, badges/pills, table headers, nav items, stat captions |
| Heading | 20px | 600 | 1.2 | `text-xl font-semibold leading-[1.2]` | Card titles, step names (Lead / Dev / QA), group titles |
| Display | 24px | 600 | 1.2 | `text-2xl font-semibold leading-[1.2]` | Page title of each screen, task title, stat numbers |

Secondary text uses the Label **size** at regular weight: `text-sm font-normal leading-normal` (helper text, log rows, table cells, timestamps, muted metadata). Buttons are Body size at weight 600: `text-base font-semibold`.

Rules
- Monospace (`font-mono`) keeps the same size as the surrounding text. Paths, branches, slugs, commands, ids, JSON, the log pane and the git status block are monospace.
- Any element that clips text (`truncate`, `line-clamp-*`, `overflow-hidden`) must use `leading-normal` (1.5), not 1.2, so Vietnamese stacked diacritics (Ế, Ộ, Ữ) are not cut off.
- Long unbroken strings (paths, branches, slugs, JSON) use `break-all`; prose uses `break-words`. Multi-line agent/plan text uses `whitespace-pre-wrap`.
- Numbers: `AB.fmtNum` (`vi-VN`, thousands separator `.`); time `HH:MM:SS` 24h; cost `≈ $0.1234`; duration `12 giây` / `1 phút 05 giây` / `1 giờ 02 phút`; date for rows older than today `DD/MM HH:MM`.

## Color

The system follows `prefers-color-scheme` and a manual toggle (D-21). Only Tailwind default-palette classes are used; every color class must have a `dark:` counterpart where it sets a color.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `bg-slate-50` | `dark:bg-slate-900` | `<body>` page background |
| Secondary (30%) | `bg-white`, `ring-slate-200` | `dark:bg-slate-800`, `dark:ring-slate-700` | Header bar, cards, dialogs, suggestion list |
| Accent (10%) | `indigo-600` fill / `indigo-700` text on light, `indigo-400` text on dark | same | See reserved list |
| Destructive | `bg-rose-600` (hover `bg-rose-700`), white text | same | Kill and nothing else |
| Text primary | `text-slate-900` | `dark:text-slate-100` | Body copy |
| Text muted | `text-slate-600` | `dark:text-slate-400` | Helper text, timestamps (>= 4.5:1 on both surfaces) |
| Log pane | `bg-slate-950` (both themes) | `bg-slate-950` | Terminal-style block; text colors below |

Accent reserved for (and nothing else):
1. Primary action button fill: Giao việc, Chạy Dev, Chạy QA, Chạy lại Lead (only when it is the first enabled action), Lưu. Exactly one primary button per card.
2. The active nav item (tinted `bg-indigo-100 text-indigo-800 dark:bg-indigo-900/40 dark:text-indigo-200`).
3. The keyboard focus outline on every interactive element.
4. The "đang chạy" state: its badge tint, the Đang chạy group accent, and the ring on the current stepper card.
5. The highlighted option in the project suggestion list and the run currently shown in the Lịch sử run table.
6. Inline text links (`text-indigo-700 dark:text-indigo-300 underline`).
7. The single data series in the CSS bar charts (`bg-indigo-500 dark:bg-indigo-400`).

Primary button hover is **darker** (`hover:bg-indigo-700`), never lighter: white on `indigo-500` is 4.47:1 and fails AA; white on `indigo-600` is 6.3:1.

Semantic state colors (status only; never used for decoration, never the only signal: every state also has a text label and a glyph)

| State | Label (exact) | Glyph | Light classes | Dark classes |
|-------|---------------|-------|---------------|--------------|
| chờ | chờ | ○ | `bg-slate-100 text-slate-700` | `dark:bg-slate-700 dark:text-slate-200` |
| đang chạy | đang chạy | ◐ (`motion-safe:animate-pulse`) | `bg-indigo-100 text-indigo-800` | `dark:bg-indigo-900/50 dark:text-indigo-200` |
| xong / Đạt | xong / Đạt | ✓ | `bg-emerald-100 text-emerald-800` | `dark:bg-emerald-900/40 dark:text-emerald-200` |

| lỗi | lỗi | ✕ | `bg-rose-100 text-rose-800` | `dark:bg-rose-900/40 dark:text-rose-200` |
| Vi phạm giao thức | Vi phạm giao thức | ✕ | `bg-rose-100 text-rose-800` | `dark:bg-rose-900/40 dark:text-rose-200` |

Profile badges (identity, not status): `work` = `bg-sky-100 text-sky-800 dark:bg-sky-900/40 dark:text-sky-200`; `personal` = `bg-violet-100 text-violet-800 dark:bg-violet-900/40 dark:text-violet-200`.

Warnings (stacking warning, dirty tree notes, plan has uncommitted edits) use the amber tint inside a callout: `rounded-xl bg-amber-50 p-4 ring-1 ring-amber-300 text-amber-900 dark:bg-amber-900/20 dark:ring-amber-700 dark:text-amber-200`. Refusal reasons use the rose equivalent (`bg-rose-50 ring-rose-300 text-rose-900 dark:bg-rose-900/20 dark:ring-rose-700 dark:text-rose-200`).

Timestamp `text-slate-400 font-mono`.

## Visual Vocabulary (text glyphs, no icon library)

Every glyph is rendered in a fixed-width `w-6 text-center` span, followed by the text variation selector U+FE0E in the JS string so platforms do not swap in colour emoji (for example `'▶︎'`). The glyph never carries meaning alone: the row/badge also has the text label, and the glyph span has `aria-hidden="true"` (log rows expose the kind through `title` and a visually hidden prefix).

| Use | Glyph |
|-----|-------|
| Log: tool call | ▶ |
| Log: assistant | ✎ |
| Log: tool result | ↩ |
| Log: final result | ✔ |
| Log: system | ⓘ |
| Log: error | ⚠ |
| Step: chờ / đang chạy / xong / needs attention / killed / lỗi | ○ / ◐ / ✓ / ! / ■ / ✕ |
| Stepper connector (md and up) | → |
| Back link | ← |
| Missing project directory | text badge `thiếu thư mục` (no glyph) |

## Screen Contracts

All screens are hash routes inside `<main id="screen">`; root element is `<section data-screen="NAME" x-data="NAME" :data-loaded="loadedAttr" class="space-y-6">` (smoke test contract, unchanged). Each screen sets `document.title` to `<Screen> · agent-brain` (see Deltas).

### Shell (index.html)
- Header bar left to right: brand `agent-brain` (Heading), nav `Tổng quan` / `Giao việc` / `Thống kê` / `Dự án` as `<nav aria-label="Điều hướng chính">`, then pushed right (`ml-auto`): profile filter and theme button.
- Profile filter: visible label `Lọc theo profile` (Label style) + `<select>` with `Tất cả` / `work` / `personal`; `title` = `Chỉ lọc danh sách và thống kê. Task mới luôn chạy bằng profile của dự án.` When the value is not `all`, every screen it affects (Tổng quan, Giao việc suggestions, Thống kê, Dự án) shows a chip in its title row: `Đang lọc: work` (profile badge colors).
- Theme button: secondary button cycling system → dark → light → system, visible text `Giao diện: hệ thống` / `Giao diện: tối` / `Giao diện: sáng`, `aria-label` = `Đổi giao diện (hiện tại: hệ thống)` etc.
- Banners under the header (full width, inside the container, `role="alert"`): session lost (rose callout) and connection lost (amber callout). Copy in the Copywriting table.

### Tổng quan (`#/`)
- Title row: `Tổng quan` (Display), filter chip when active, busy text when present (muted: `Đang chạy: web-ban-hang · run 3 (lead)`), and a primary link-button `Giao việc` to `#/assign`.
- Four group cards in a grid `grid gap-6 lg:grid-cols-2` (2 x 2 from 1024px, one column below), in this order: `Đang chạy`, `Chờ bạn`, `Lỗi / cần xử lý`, `Xong`. Group card header: group title (Heading) + count in a slate pill + a one-line hint (helper text). Accent line on the left edge of the card header is not used; the group is identified by title and count only.
- Task item inside a group (the whole item is one link to `#/task/ID`, `rounded-xl p-4 ring-1 ring-slate-200 hover:bg-slate-50 dark:ring-slate-700 dark:hover:bg-slate-700/50 space-y-2`):
  1. Title = the request text, `font-semibold leading-normal line-clamp-2`, full text in `title`.
  2. `project · slug` in helper style, `slug` monospace, `truncate`.
  3. Row of: profile badge, then three step pills `Lead`, `Dev`, `QA`. Each pill is a badge with glyph + role + state colour, e.g. `✓ Lead`, `○ Dev`; the full state label (`Lead: xong`) is in `title` and `aria-label`. Pills are never colour-only.
  4. Banner text (Label style) and `Cập nhật HH:MM:SS` (helper).
- The `Xong` group shows its 10 newest tasks and a secondary button `Hiện thêm 10` until all are shown (the list request asks for `limit=100`). The other groups show all items.
- Refresh every 4 s and on `ab:profile` (unchanged from 05-08).

### Giao việc (`#/assign`)
One card, `space-y-6`, single column, `max-w-3xl` inside the container (forms read better narrow). Order: Yêu cầu, Dự án, Tên task, preflight panel, action row.
- `Yêu cầu (tiếng Việt)`: textarea, 5 rows, `maxlength="20000"` (server limit), placeholder `Ví dụ: thêm nút đăng xuất ở trang tài khoản`.
- `Dự án`: combobox (see Interaction Contracts). Under it: helper `Gõ tên, alias hoặc tên không dấu rồi chọn trong danh sách`. After a choice: a chip with `name_vi (id)`, the profile badge, and the note `Task chạy bằng profile <profile> của dự án — đổi profile dự án trong projects_map.json, không đổi ở đây` (helper style). The profile is displayed, never editable.
- `Tên task (slug)`: monospace input, `maxlength="48"`, helper `Tạo từ yêu cầu như CLI, có thể sửa`.
- Preflight panel (appears once a project and a slug exist, `aria-live="polite"`): lines `Nhánh hiện tại: <branch>` (monospace branch) and either `Sẽ tạo nhánh task/<slug>` or `Lập lại plan trên nhánh hiện tại (task/<slug>)`; amber callout for the stacking warning; rose callout for a refusal reason with dirty files in a monospace block. All reason text comes verbatim from the server.
- Action row: primary `Giao việc` (`disabled` per `startDisabled`) and, under it, `disabledReason` in helper style (always visible while disabled, `id` referenced by `aria-describedby` on the button).
- Candidates (409): amber callout `Tên khớp nhiều dự án — chọn một:` followed by selectable rows (same row recipe as suggestions).
- Job failure: rose callout with the heading `Lead dừng sớm` and the output lines in a monospace block.

### Chi tiết task (`#/task/ID`)
Vertical order: header card, stepper card, (blocked / needs-fix callout), plan card, QA card (only if a report exists), log card, Lịch sử run card. Rationale: what to decide on first (state + next action), then evidence (plan), then live detail.
- Header card: `← Tổng quan` link; task title (Display, `line-clamp-3`, full text in `title`); line `project name (id)`, profile badge, branch (monospace, `break-all`); the banner as a badge (Badge recipe, glyph + banner text) coloured by group: running and waiting use the đang chạy / indigo tint, attention uses amber (`blocked`, `qa_fix`) or rose (failed, killed, protocol violation), done uses emerald.
- Stepper card (`<ol aria-label="Pipeline Lead, Dev, QA">`): `flex flex-col gap-4 md:flex-row md:items-stretch`; each step is `<li class="flex-1 min-w-0">` (a card-in-card: `rounded-2xl p-6 ring-1 ring-slate-200 dark:ring-slate-700 space-y-4`), joined by `<li aria-hidden="true" class="hidden items-center text-slate-400 md:flex">→</li>`. The current step carries `ring-2 ring-indigo-600 dark:ring-indigo-400` and `aria-current="step"`. Step card content: role name (Heading), state badge (glyph + label), then three lines in secondary text style: `Token: vào X · ra Y · cache R / W`, `Thời gian: <fmtDuration>`, `Chi phí: ≈ $C`. A step without a run shows `Chưa chạy` instead of the three lines; a running step with no `result` yet shows `—` for unknown token figures. Action buttons render at the bottom of the current step card only (`flex flex-wrap gap-2`), with each disabled button's reason under it (helper style, `aria-describedby`).
- Callouts (D-03): when `isBlocked` an amber callout with heading `Dev dừng vì vướng mắc` and body `Sửa .plan.md trong editor của bạn rồi commit với message '<slug>: plan', hoặc chạy lại Lead.`; when `isQaFix` an amber callout `QA kết luận Cần sửa` with body `Xem báo cáo QA bên dưới. Sửa .plan.md rồi commit '<slug>: plan', hoặc chạy lại Lead; sau đó chạy lại Dev.` These sit between the stepper and the plan card, and the Vướng mắc section / QA card get an additional `ring-2 ring-amber-500 dark:ring-amber-400`.
- Plan card, QA card, log card, runs card: contents exactly as plan 05-10 with the class recipes and copy of this file. The plan changes table (`File | Dòng / hàm | Sửa gì | Lý do`) is a Table recipe with the File cell monospace `break-all`.
- Log card: see Interaction Contracts (log pane).
- Finished pipeline (`qa_pass`): below the stepper, helper text `Pipeline đã xong. Kiểm tra và merge nhánh '<branch>' bằng git.` `[ASSUMED U2]`.

### Thống kê (`#/stats`)
- Title row: `Thống kê` (Display), filter chip when active, right side a labelled select (`Khoảng thời gian`: `7 ngày` / `30 ngày` / `Tất cả`, default 30 ngày) and below the title the note `Chi phí là giá trị tương đương theo API, không phải hóa đơn`.
- Totals: `grid grid-cols-2 gap-4 lg:grid-cols-5` of cards using the Card recipe unchanged (`p-6`). Each: caption (Label) and value (Display): `Số run`, `Token vào`, `Token ra`, `Cache đọc / ghi` (two numbers `R / W`), `Chi phí ≈`.
- `Theo ngày` card: fixed-height chart `h-40` flex row `items-end gap-1`; each day is a column (`flex-1 min-w-0`) whose bar is `w-full rounded-t-md bg-indigo-500 dark:bg-indigo-400`, height from `colStyle` (object), minimum 2% when non-zero, 0 when zero. ## Interaction Contracts

**Project picker (Giao việc, D-05, DASH-07).** ARIA combobox: the input has `role="combobox" aria-autocomplete="list" aria-expanded aria-controls="ab-suggest" aria-activedescendant`; the list is `<ul id="ab-suggest" role="listbox">` (`mt-2 max-h-64 overflow-y-auto rounded-xl bg-white ring-1 ring-slate-300 dark:bg-slate-800 dark:ring-slate-600`), options `<li role="option" id="ab-opt-N">` min height 40px. Keyboard: `ArrowDown` / `ArrowUp` move the highlight (indigo tint `bg-indigo-100 text-indigo-900 dark:bg-indigo-900/40 dark:text-indigo-100`), `Enter` chooses the highlighted option, `Escape` closes the list, `Tab` leaves. Mouse: click chooses. Missing projects render greyed (`opacity-60`), `aria-disabled="true"`, are skipped by the arrow keys and are not choosable. Typing after a choice clears the choice (the button disables again). The list shows `Đang tìm...` while a request is in flight longer than 200 ms and the empty copy when nothing matches. Only a listed option can be chosen; the typed text is never sent.

**Stepper (D-23).** States, labels and glyphs as in the Color table; the three steps always render in the order Lead, Dev, QA; at most one step is "current" (the server's `current_step`). Buttons follow the server's `actions` order: the first enabled action is the primary button, every other action is secondary, Kill is destructive. A button that is disabled shows the server's reason in plain text under it; nothing is hidden. While an action request is in flight every action button is disabled and the clicked one shows `Đang giao...` (Kill: `Đang dừng...`).

**Next-step buttons (D-01, D-03).** Nothing chains. After Lead: banner `Chờ duyệt plan`, primary `Chạy Dev`. After Dev: primary `Chạy QA`. Blocked / needs-fix: the CLI's next steps only, as buttons (`Chạy lại Lead`, `Chạy Dev`).

**Dialogs (Kill, Chạy lại Lead, raw JSON).** One in-page dialog pattern: `role="dialog"` (`role="alertdialog"` for Kill and Chạy lại Lead) with `aria-modal="true"` and `aria-labelledby`; focus moves into the dialog on open (the safe button for confirmations, `Đóng` for JSON) and returns to the trigger on close; `Escape` closes; clicking the overlay closes the JSON viewer but not a confirmation. Background is not scrollable while open (`overflow-hidden` on `<body>` through a class toggled by JS).

**Log pane (D-22).**
- Container: `<div id="ab-log" role="log" aria-live="off" aria-label="Log realtime" tabindex="0" class="h-96 overflow-y-auto rounded-xl bg-slate-950 p-3 text-sm leading-normal lg:h-[32rem]">` (keyboard users can scroll it; screen readers are not flooded).
- Row = a `<button type="button">` (`flex w-full items-start gap-3 rounded-md px-3 py-1 text-left hover:bg-slate-800 motion-safe:transition-colors` + a light focus outline `focus-visible:outline-2 focus-visible:outline-indigo-400`), columns: time (`w-20 shrink-0 font-mono text-slate-400`, `HH:MM:SS`), glyph (`w-6 shrink-0 text-center`), text (`min-w-0 flex-1 break-words`, colour per kind; tool, tool_result and the path/command parts are monospace). One row per event, same wording as the CLI line.
- Follow behaviour: auto-scroll to the bottom while `follow`; scrolling more than 40 px above the bottom pauses it and shows the floating button `Về cuối (live)` (secondary recipe on the dark pane: `absolute bottom-4 right-6`, container wrapped in `relative`); reaching the bottom or pressing the button resumes. A paused pane keeps receiving rows silently.
- `system/thinking_tokens` rows hidden by default; toggle button text `Hiện thinking_tokens (N đang ẩn)` / `Ẩn thinking_tokens`.
- Retention: at most 5000 rows in memory (oldest dropped); when dropping starts the pane shows a first, non-interactive muted row `Đã ẩn các dòng cũ hơn — giữ 5000 dòng mới nhất`.
- Raw JSON: row click opens the JSON dialog titled `Dữ liệu thô (events.raw_json) · run N · dòng SEQ`, body a monospace `<pre>` bound with `x-text` (`max-h-[60vh] overflow-auto`), button `Đóng`.
- Stream status line above the pane: `run N · role · status` + stream state text. States: `đang kết nối`, `live`, `mất kết nối — đang thử lại...`, `đã kết thúc`, `lỗi`. Reconnect and end handling as in plan 05-10.

**Polling and freshness.** Overview 4 s, task detail 3 s, Stats / Dự án on load, on filter change and on the user's actions (as in the plans). A failed poll keeps the last data on screen and shows the muted line `Không cập nhật được — đang thử lại...`; the connection-lost banner appears after two consecutive failed polls.

**Profile filter (D-15, D-16).** Pure view state in `localStorage['ab.profile']`, default `all`. It never appears in any POST/PUT body.

**Theme (D-21).** `localStorage['ab.theme']` = `system` | `dark` | `light`; applied before first paint by `theme.js`; follows `prefers-color-scheme` live while `system`.

**Keyboard and focus.** Every interactive element is a native `<a>`, `<button>`, `<input>`, `<select>`, `<textarea>` (no clickable `div`), has the FOCUS outline, and a logical tab order equal to visual order. Hash navigation moves focus to `<main id="screen">` (`tabindex="-1"`) after each route change.

**Reduced motion.** The only animation is the running-glyph pulse and colour transitions, both behind `motion-safe:`.
