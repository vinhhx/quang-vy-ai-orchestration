## What changes (summary)

1. **New screen Cài đặt (`#/settings`)**, new last nav item. Four sections behind a sub-nav: `Đội hình`, `Quy trình`, `Nhân sự`, `Engine`. Teams, workflows and staff are created / edited / copied / deleted inline; engines are a read-only readiness list. Built-ins are read-only but can be copied (`Nhân bản`). Every write shows save / validation / error / conflict states.
2. **Giao việc** gets an `Đội hình` radio list directly under `Quy trình`, default = the project's team, description visible on every option.
3. **Task screen**: team line + `Đổi đội hình` + history in the pipeline info block; engine shown on every stage card and every ledger row; a **quota stop banner** (`Hết quota engine X`) with `Chạy lại bước này bằng đội hình…` and `Thử lại sau`; a **human-step callout** (`Chờ <tên> làm`) with `Xong` and `Trả lại`.
4. **Thống kê**: two new cards, `Theo engine` (tokens and cost by engine) and the QA `Cần sửa` rate by Dev engine.
5. **Tổng quan**: one hint and two banner texts for the new waiting states (small delta).
6. **Vocabulary**: five new state words (`chờ người`, `hết quota`, `thiếu key`, `thiếu lệnh`, `chưa kiểm`) mapped onto existing color families; the delete-confirm button may use the destructive recipe (extension of the "red = Kill" rule, see Color).

Order of the task screen, top to bottom (05.2 order, with two additions): header card, stop banner (autopilot stop **or quota stop**), pipeline card, **human-step callout** (when a human step is waiting or was rejected), D-03 callouts, ledger card, plan card, QA card, log card.

## Screen Contract — Cài đặt (`#/settings`)

### Shell and route

- Nav: a sixth item `Cài đặt` after `Dự án` (nav item recipe, `aria-current="page"` on the route). `index.html` nav, `screenTitles.settings = 'Cài đặt'`, `parseHash` `#/settings`, `document.title` `Cài đặt · agent-brain`. Root element `<section data-screen="settings" x-data="settings" :data-loaded="loadedAttr" class="space-y-6">`.
- The router loads only `/js/settings.js` for this route: either one file or the file loads its helpers itself; the planner must not rely on a second `loadScript` call from the router.
- Data loads on entering the screen and on `Đọc lại`. No polling, no SSE. The profile filter has no effect here.

### Page frame

1. Title row `flex flex-wrap items-center gap-4`: `<h1>` `Cài đặt` (Display); `Đọc lại` Secondary button with `ml-auto` (in flight `Đang đọc...`) re-reads `teams.json`, `workflows.json` and the staff list. It does not re-check engines (that button is inside the Engine section).
2. Intro helper: `Đội hình, quy trình và nhân sự lưu trong ~/.config/agent-brain/ và vẫn sửa tay được trong editor; sửa tay xong bấm Đọc lại. Engine chỉ xem.`
3. **Naming rule (D-11), always visible under the intro** (helper style): `Đội hình và quy trình là hai danh sách riêng nên được trùng tên (ví dụ mac-dinh). Mọi nơi hiện tên đều ghi rõ là đội hình hay quy trình.`
4. Sub-nav `Mục cài đặt`: `Đội hình` · `Quy trình` · `Nhân sự` · `Engine`. One section visible at a time (`x-show`, so an open draft survives a switch). Default `Đội hình`; the last choice is kept in `sessionStorage['ab.settings.section']` `[ASSUMED C2]`.
5. A status line `aria-live="polite"` under the sub-nav shows the last result (`Đã lưu đội hình {name}.` etc.); it is cleared by the next action.

### Shared write behaviour (all three editable sections)

- **Only one editor open per section.** While a draft is open, the creation button and every row action in that section are disabled, and one helper line above the list explains: `Đang sửa {name} — lưu hoặc hủy trước khi sửa mục khác.`
- **Built-ins are read-only.** A built-in row shows the `có sẵn` chip and only `Nhân bản`. A hand-edited override (`source: override`) is a file entry: it shows `ghi đè … có sẵn` and keeps `Sửa`, `Nhân bản`, `Xóa`. The editor never accepts a built-in name for a new entry (`'{name}' là đội hình có sẵn, không ghi đè được. Đặt tên khác.`) `[ASSUMED C3]`.
- **Name / id is immutable after creation** (the input is read-only with `aria-readonly="true"`; helper `Không đổi tên được vì dự án và task tham chiếu theo tên. Muốn tên khác: bấm Nhân bản.`). `Nhân bản` opens a new-entry editor prefilled from the source with name `{name}-ban-sao` (then `-ban-sao-2`, ...), the first free one, and focus on the name field with its text selected.
- **Validation runs twice.** The client mirrors the cheap rules for instant feedback (inline, per field, `aria-invalid`); the server answer is authoritative and uses the same rules as the file loader. Errors never block typing. `Lưu …` is disabled while a client rule fails, with the first failing reason visible under the button (Phase 5 disabled-reason pattern). On submit: the button reads `Đang lưu...`, all editor controls are disabled, the request is the same for create and update.
- **Server refusal (422 / 409 other than conflict).** Rose callout above the buttons, heading `Không lưu được {đội hình | quy trình | nhân sự}`, one line per server error (at most 10, then `… và {k} lỗi khác`), `role="alert"`, focus moves to the callout. Field-keyed errors also appear under their field. The draft stays.
- **Conflict (file changed elsewhere, 409 `conflict`).** The list is reloaded, the draft stays in the form, and a rose callout reads: heading `{teams.json | workflows.json | file nhân sự} vừa bị sửa ở nơi khác`; body `Đã tải lại danh sách. Bản nháp của bạn vẫn còn trong form — kiểm tra rồi lưu lại.` `[ASSUMED C5]`.
- **Invalid file blocks all writes.** When `teams.json` / `workflows.json` has load errors, the section shows the amber error callout, and every write control (create, edit, copy, delete) is disabled with the reason `{file} đang có lỗi — sửa file trong editor rồi bấm Đọc lại; dashboard không ghi đè file lỗi.` shown once under the callout. Reading and reloading still work.
- **Success.** The editor closes, the list is replaced by the server response (so `summary` strings come from the server), the status line says `Đã lưu …`, and focus returns to the row's `Sửa` button (or to the creation button after create). The saved write is atomic server-side (D-10); the UI shows nothing about temp files.
- **Delete.** Row `Xóa` (secondary) opens an `alertdialog` (initial focus on the safe button, Escape closes, overlay click does not): copy in Copywriting. The confirm button is destructive (rose). After success the status line says `Đã xóa …` and focus goes to the section's creation button.
- **Leaving the screen with an open draft** discards it without a prompt (no guard, as the rest of the dashboard) `[unresolved, see UI Considerations]`.

## Interaction Contracts (delta)

- **Focus and tab order** = visual order. Settings: page title row, sub-nav, section creation button, list rows top to bottom (row actions left to right), editor fields in DOM order. Task: quota banner buttons, header toggle, team line, flow region, human callout buttons, action strip, ledger rows, plan / QA / log.
- **Dialogs** (change-team, re-run, three delete confirms): the 05 mechanics (focus moves in, Escape closes, focus returns to the trigger, background scroll locked, overlay click does not close). Delete confirms are `alertdialog` with initial focus on the safe button; the two team dialogs are `dialog` with initial focus on the selected (or first) radio.
- **Radio and checkbox groups** are native: arrow keys move a radio selection, Space toggles a checkbox, Tab leaves the group; disabled loop checkboxes are skipped by Tab and carry their reason in `aria-describedby`.
- **Forms**: Enter in a single-line field does not submit when the form is invalid; Enter in a textarea inserts a newline. After a failed client validation focus moves to the first invalid field; after a server refusal it moves to the error callout.
- **Announcements**: the Settings status line and the quota banner are `aria-live="polite"`; the human callout is `role="status"`; none of them interrupt typing.
- **Reduced motion**: only `motion-safe:animate-pulse` (running glyph, unchanged) and `motion-safe:transition-colors`. The new `chờ người` glyph does not animate.
- **Concurrency**: all task actions are disabled while one is in flight (Phase 5 rule); all Settings write controls are disabled while any Settings write is in flight.
- **Secrets**: no DOM text, `title`, `aria-label`, log line or toast ever contains an engine key value; a test greps the rendered Engine section and the log pane for the value of a planted key (ENG-05).
