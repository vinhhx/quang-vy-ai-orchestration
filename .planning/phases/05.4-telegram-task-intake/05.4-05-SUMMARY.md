# Phase 05.4 Plan 05: `/task` intake from Telegram Summary

**Typed `/task` flow (request -> allowlisted project -> workflow -> confirm) that creates exactly one Telegram-origin task through the dashboard's own `start_new_task`, with a strict separate callback grammar, a fail-closed `telegram_projects` allowlist and one open interaction at a time**

## Accomplishments

- `telegram/intake.rs`: constants and types of the plan's interface, `parse_command` (first token only, `@bot` suffix, 1-32 of `a-z0-9_`), `is_forwarded`, `allowed_projects` (fail closed, list order, at most 30, missing/media/unrunnable dropped, unknown ids reported), `slug_candidates` (`-2` … `-5` within 48 chars), `take_expired`, and the handlers. The dry-run slug search and the final `start_new_task(dry_run: false)` are the only creation path; the allowlist is re-read at `Tạo task`.
- `callback.rs`: `IntakeOp` (`P W T A N G C X`), `IntakeCb`, `encode_intake`, strict `decode_intake` (8-hex flow, index required only for P/W/T, `0..=99` without sign or leading zero, ≤ 64 bytes). The file diff against the base has only added lines; `decode`, `encode`, `Op`, `ALL_OPS` and their tests are byte-identical.
- `bot.rs`: `on_message` routes a forward to `intake::on_forward` before any command parsing, then commands, then a waiting request, then the 05.3 note/help path; `i`-prefixed callbacks go to `intake::on_callback` before the 05.3 decode (no 05.3 op code is `i`); `intake::tick` runs next to each `expire_prompt`; `ask_note` closes an open flow; new `send_message`; `send_prompt` is `pub(crate)`; new `HELP_TEXT`.
- Terminal lines carry character counts, project, branch, job id and refusal kind only; tests assert no `Telegram:` line contains the request or the forwarded text.
