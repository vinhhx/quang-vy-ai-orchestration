<objective>
Close the loop of a Telegram task request: tell the user the task id once it exists (or why the job failed before a task existed), bound how many tasks Telegram may create per day, and register the `/task` / `/huy` command menu.

- Task 1 (tracer): outcome watcher on the poll thread — `Đã tạo task N` after a successful start, the failure report for a job that dies before its row exists, fast polling only while watching.
- Task 2: daily cap from `config.json`, counted from the database (survives restarts), checked at `/task` and again at `Tạo task`.
- Task 3: `setMyCommands` after getMe, fake Telegram support, and the 05.3 stranger test's allowed-method list.

Purpose: INTAKE-10 (research Pitfall 3), INTAKE-04 (OD-2), INTAKE-01 (command menu, OD-5). Requirement IDs are research-proposed, not yet in REQUIREMENTS.md.
Output: `intake.rs`, `bot.rs`, `config.rs`, `telegram/mod.rs`, fake Telegram, tests.
</objective>
