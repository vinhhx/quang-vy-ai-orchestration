# Phase 05.4 Plan 03: Dashboard-only approval for Telegram tasks Summary

**Plans of Telegram-created tasks can only be approved on the dashboard: no `Duyệt plan` button on their Telegram messages, a server-side refusal in the shared `run_control_as` approve branch for any Telegram-sourced approval, and one-line (max 120 character) titles in every notification.**

## Performance

- **Duration:** about 35 min (a cold cargo build of an empty target dir ran in parallel with the edits)
- **Completed:** 2026-10-22
- **Tasks:** 2
- **Files modified:** 4 (3 modified, 1 created)

## Accomplishments

- `TaskState.origin` is filled from `db::task_origin`; `ActionSource` and `run_control_as` carry the source; `run_control` delegates as `Dashboard`, so `post_control` and every other caller are unchanged. The approve arm refuses `Telegram` + origin `telegram` with `TELEGRAM_APPROVE_REFUSED` (kind `not_allowed`) before `claim::approve_check`.
- bot.rs runs button presses (`act`) and `Trả về Lead` (`perform_return`) as `ActionSource::Telegram`; the existing `apply_outcome` turns the refusal into an alert answer and keeps the message tracked.
- render.rs: `approve_offered` gates `Duyệt plan` in both the Gate and RunFailed arms; the gate text gets `TELEGRAM_ORIGIN_LINE` right after the project line; `title_line` is used in the Gate, Stop, QaPass and RunFailed texts.
- `tests/telegram_intake.rs` created with the copied harness helpers and three tests: `gate_without_approve_button`, `forged_approve_refused`, `gate_title_is_first_line`.
