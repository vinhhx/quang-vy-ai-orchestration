# Phase 05.4 Plan 07: forwarded messages become one task Summary

**Messages forwarded to the bot are collected in a 2-second window and shown as one ☑/☐ list. The user picks messages, then a project, a workflow and an optional instruction. `Tạo task` then creates exactly one Telegram-origin task. Its request quotes each picked message with its sender and local time inside the nonce-delimited untrusted block, and that framing is kept when the task goes back to the Lead.**

## Accomplishments

- New `telegram/forward.rs`. It reads only `forward_origin`, `text` and `caption`, and never looks at file ids.
  - Sender labels for user, hidden user, chat and channel origins, with an unknown fallback. Each label is one line of at most 80 characters.
  - Local `YYYY-MM-DD HH:MM` time labels.
  - The selection text and the keyboard. Each toggle's data is `iT:{flow}:{index}`, so no text or state goes into the callback data.
  - `to_quotes` for the composer.
  - The `AGENT_BRAIN_TELEGRAM_INTAKE_QUIET_MS` clamp.
- `intake.rs`, the forwarded flow:
  - `on_forward` opens the flow or appends to it. The 20-message cap sends `OVER_CAP` once, and messages without text are counted as skipped.
  - `tick` closes the collection window after the quiet time or 10 s. At that point it checks the daily cap and the allowlist and sends the selection message synchronously.
  - Toggle, `Chọn hết`, `Bỏ hết` and `Tiếp tục` work in `Select`. `Tiếp tục` refuses with an alert when nothing is selected or the batch is too long.
  - After `Tiếp tục`, the flow uses the typed flow's project, workflow and confirm steps.
  - The confirm screen shows the number of picked messages and the instruction. A text sent at this point becomes the instruction and names the branch.
  - `Tạo task` passes `compose_forwarded(...)` unchanged to `start_new_task` with `Origin::Telegram`.
  - `poll_timeout_secs` returns 1 while forwards are being collected.
- `HELP_TEXT` now tells the user to forward messages here.
- Terminal audit lines carry only counts, never forwarded text or the instruction. Tests assert this.

## Deviations from Plan

### Auto-fixed / adjusted

**1. [Rule 1 - Test made obsolete by the planned behaviour] `forwarded_task_is_not_a_command` (plan 05.4-05)**
- **Found during:** Task 1
- **Issue:** The test expected a forwarded `/task sửa app` to get the help reply. That was the 05.4-05 stub of `on_forward`, which this plan replaces with collection.
- **Fix:** The test now starts serve with the 300 ms window. It asserts a selection message `Đã nhận 1 tin chuyển tiếp` that contains `/task sửa app`, no help reply, no `/task` flow message, and no forwarded text on the terminal. The guarantee is the same (a forward is never a command), checked against the new behaviour.
- **Files modified:** agent-brain/tests/telegram_intake.rs
- **Commit:** bd4f0b7

**2. [Determinism] `push_burst` test helper**
- **Issue:** The plan's tests push a burst and expect exactly one selection message. With separate `push_update` calls, a test thread descheduled for more than 300 ms between pushes would split the burst into two windows.
- **Fix:** `push_burst` writes all updates of a burst to a new file and renames it over the fake's `updates.jsonl`. The fake reads the whole burst or none of it, so serve handles the burst in one `getUpdates` answer. Single late forwards, which the tests want to arrive after the window, still use `push_update`. No sleeps were added; every wait is on a recorded event. Like `wait_polling`, the helper uses the fake's public `dir` and does not change `tests/support/telegram.rs`.

**3. [Event wait instead of a timed window] `stranger_forward_ignored`**
- The plan says "no selection within 2 s". The test instead waits for three events: the stranger line, the offset acknowledging the update, and two further `getUpdates` calls. Any open 300 ms window would have closed by then. It then asserts that no message was sent at all. Finally it checks that a paired forward afterwards yields `Đã nhận 1 tin chuyển tiếp`.

**4. [Rule 2 - small addition] `/huy` while collecting**
- `/huy` during the window has no message to edit, so it replies `Đã huỷ — không tạo task.` instead of closing silently.

**5. [Test additions beyond the plan]**
