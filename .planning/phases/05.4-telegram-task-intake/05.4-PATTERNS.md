## Pattern Assignments

### `src/dashboard/api_tasks.rs`: `start_new_task` extraction (service, request-response)

**Analog:** the 05.3 `run_control` extraction in the same file. `ControlOutcome` (L1593-1621) is a plain enum with no axum types; `run_control` (L1637) returns `BrainResult<ControlOutcome>`; `control_response` (L1779) maps it to the SAME status codes/bodies; `post_control` (L1820) is `blocking(move || run_control(...))` then map. Copy that shape for creation.

**Source body to move** (`create_task`, L502-667). Keep this order: trim/empty check -> `MAX_REQUEST_CHARS` -> slugify -> `load_map` + `resolve_project` -> `workflows::resolve` -> `lead_preflight` -> argv -> `jobs.start`.

Validation (L503-526):
```rust
let trimmed_req = body.request.trim();
if trimmed_req.is_empty() { /* 422 "Yêu cầu không được để trống" */ }
if trimmed_req.chars().count() > MAX_REQUEST_CHARS { /* 422 "Yêu cầu quá dài (tối đa {MAX_REQUEST_CHARS} ký tự)" */ }
let name_or_req = body.name.as_deref().unwrap_or(trimmed_req);
let slug = crate::routing::slugify(name_or_req);
if slug.is_empty() { /* 422 "Không thể tạo tên task từ yêu cầu — hãy truyền cờ --name <slug>" */ }
```
Project, workflow, preflight (L528-570):
```rust
let map = crate::projects::load_map(&st.map_path)?;
let (project, proj_root) = match resolve_project(&map, &st.cfg, &body.project) { Ok(p) => p, Err(refusal) => ... };
let loaded = crate::workflows::load(&st.cfg);
let project_default = crate::projects::workflow_of(&map, &project.id);
let workflow = match crate::workflows::resolve(&loaded, body.workflow.as_deref(), project_default.as_deref()) { Ok(r) => r.workflow, Err(e) => /* 422 e.message */ };
let conn = crate::db::open(&st.db_path)?;
let pf = lead_preflight(&conn, &st.jobs, &project, &proj_root, &slug)?;
if !pf.can_start { /* 409 {"error": pf.reason, "kind": pf.kind} */ }
```
Argv after `--` (L571-607): `auto` role -> `["auto","--start","--name",slug,"--workflow",wf,"--",project.id,request]`; otherwise `["run","lead","--name",slug,"--workflow",wf,"--",project.id,request]`. Append `"--origin","telegram"` BEFORE the `--` only when `origin == Telegram`.

Job start error mapping (L626-660): `e.message.contains("Dashboard đang dừng")` -> 503 `Unavailable`; else 409 `kind:"busy"`. In the enum these become `StartOutcome::Unavailable` and `StartOutcome::Busy(String)`.

**Rules for the planner:**
- Keep `NewTask` (L25-34, `deny_unknown_fields`) byte-for-byte; no `origin` field (browser must not set it).
- `create_task` handler maps `StartOutcome` -> existing JSON (202 body keys `job_id, project, slug, branch, workflow, auto`, optional `warning`). The 17 `/api/tasks` posts in `tests/dashboard_run.rs` plus `dashboard_kill`, `dashboard_autopilot`, `dashboard_pipeline`, `telegram_outage`, `telegram_actions` are the regression net.
- `dry_run: true` must run everything up to and including `lead_preflight` and return `Ready` without `jobs.start`.
- Telegram retry on slug collision (OD-8): loop in the intake module around `start_new_task(dry_run:true)`, not inside the function; refuse `replan == true` for `Origin::Telegram`.
- Do NOT put `Origin` into `LeadPreflight` (it is `Serialize` and served by the preflight endpoint; keep JSON unchanged).

## Shared Patterns

### Reuse the dashboard's own function, never reimplement
**Source:** `src/dashboard/api_tasks.rs` (`start_new_task` after extraction; `run_control_as`); `src/dashboard/api_runs.rs::kill_run` (L75).
**Apply to:** every intake action. Guards (from RESEARCH): `grep -rn "start_new_task" agent-brain/src/telegram` shows exactly the intake call site; `! grep -rn "jobs\.start" agent-brain/src/telegram`. This replaces the 05.3 gate `! grep -rnE "create_task|NewTask"`.

### Trust boundary: authz first
**Source:** `src/telegram/bot.rs` L86-129 (`authz`) and `handle_update` L381-405.
```rust
match authz(update, ctx.cfg.chat_id) {
    Authz::Skip => return,

    Authz::Paired => {}
```

**Apply to:** all new routing; chat id AND sender id both checked before any field is read.

### Outbound messages: plain text, outbox for edits
**Source:** `bot.rs::edit` L1116, `edit_result` L1136, `reply` L1152, `answer` L1098; `Outgoing::{Edit,Keyboard}` in `src/telegram/outbox.rs`. No `parse_mode` anywhere (`! grep -rn parse_mode agent-brain/src/telegram`).

### Terminal output and audit
**Source:** `src/term.rs` (`emit` stderr, `emit_out` stdout); `bot.rs::audit` L976. Never log request text, forwarded text or token; counts and lengths only.

### Vietnamese error copy
**Source:** 05.3-PATTERNS.md item 10 and `api_tasks.rs` strings above. Name the thing and the fix, e.g. `Chưa có telegram_projects trong projects_map.json — thêm id dự án được phép để giao việc từ Telegram.`

### Background-thread / own DB connection
**Source:** `src/dashboard/pump.rs`, `src/telegram/detect.rs`. For the outcome watcher (job exited, no task row): poll `st.jobs.get(job_id)` and `db::find_task_by_branch` on each loop turn of `run_poll`; do not add a thread.

**Source:** `src/telegram/setup.rs::new_code` L23-34 (`/dev/urandom` + `read_exact`).

### Tests never touch api.telegram.org
**Source:** `tests/support/telegram.rs` header and `FakeTelegram::env()` (`AGENT_BRAIN_TELEGRAM_API`, `AGENT_BRAIN_TELEGRAM_BACKOFF_MS=200`). Use the obviously fake token `FAKE_TOKEN`.
