<objective>
Give the protocol its other two roles.
- Dev reads only `.plan.md` and the files it names, edits only those, writes Vướng mắc and stops when the plan is incomplete, and commits as `{task}: <mô tả ngắn>`. This is enforced by tool limits, a read/write guard hook and a post-run git check, not by the prompt alone (ROLE-02, ROLE-03, ROLE-06, D-12).
- QA reads the diff since the plan commit and writes `.qa-report.md` without touching code (ROLE-04, D-15, D-16).
- One test runs the whole lead → dev → qa chain (ROLE-05).

Purpose: the core value is "đúng vai trò". This plan makes each role's limits mechanical.
Output: `brain dev` and `brain qa` wired through `cli.HANDLERS`, the guard hook, two prompt files, and e2e tests against the fake claude.
</objective>

## Plan notes

- Runs in parallel with 02-02 and 02-04. This plan is the only wave-2 plan that modifies `tests/fakes/fake_claude.py`. It must not modify any file created in 02-01 other than the fake.
- Shared file-format contract with plan 02-04: the guard log is `<run_dir>/guard.jsonl`, one JSON object per decision with keys `ts`, `tool`, `path`, `decision` (`allow` | `block`) and `reason`. Plan 02-04 counts the `block` lines for the task log.
- Why a hook: Claude Code does not ask permission for Read, Grep or Glob (A-04), so `--allowedTools Read(./x)` cannot stop Dev from reading other files. A PreToolUse hook passed with `--settings` is the only mechanical read limit available to a script. The post-run git check is the backstop when the hook mechanism turns out not to fire (A-05), and plan 02-05 checks that live.
- D-12 lets the script either run "Cách kiểm tra" or print it. Printing is chosen because those commands are written by an LLM and would run unreviewed in the user's repo (T-02-15).
- Discretion choice (D-12 / Claude's Discretion): Dev keeps `Bash(git add *)` and `Bash(git commit *)` and may commit itself. brain then commits whatever in-plan change is still pending, so ROLE-02 holds either way.
