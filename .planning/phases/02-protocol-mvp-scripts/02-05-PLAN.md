## Plan notes

- `checkpoint:human-action` is used, not human-verify, because the work itself (real agent runs on the user's machine and accounts, picking real tasks, judging QA findings) can only be done by the user. `workflow.human_verify_mode` is the default `end-of-phase`, which does not suppress human-action checkpoints. Both checkpoints carry `gate="blocking-human"`: auto-approving them would fake the phase gate.
- Task 1 creates one test file and runs checks. No production code changes in this plan. When the live run finds a defect, the executor records it in the SUMMARY as a gap for `/gsd-verify-work` and gap closure, and does not patch brain/ inside this plan.
- ROLE-07 takes calendar time (spec estimate: 1-2 weeks, mostly trying and tuning prompts). The executor may stay paused at Task 3 for that long; the resume signal carries the result.
- Prompt tuning during the five tasks is expected. When the user edits brain/prompts/*.md, the verbatim spec lines at the top must stay (tests check them), or the user says so in the resume message and the executor reports which tests need updating.
