<objective>
Tracer slice: one real `agent-brain run lead` path, wired through every layer this phase builds, tested end to end against the Phase 2 fake claude.

CLI (clap) → config → projects map + Vietnamese routing (Fallback Ask) → profile env → git task branch + `.plan.md` skeleton → SQLite task row → runner (own process group, byte stream reader, current-thread Tokio) → stream classification + summary → events/runs rows → terminal lines → ROLE-01 post-check → `.plan.md` commit.

- Task 1 (tracer): the run-lead happy path end to end, on profiles work and personal.
- Task 2: entry points for every other command (so owner plans edit disjoint files) and the run-lead refusal paths (Fallback Ask, dirty tree, empty profile, missing claude, bypass flag, bad JSON, usage errors).

Purpose: prove the architecture on one path before five wave-4 plans expand it in parallel. Plan 03-03 already built the library and storage layers; this plan adds the binary, the runner, the stream parser, the terminal output and the roles layer, and fixes the module layout so wave-4 plans edit disjoint files.
Output: a working `agent-brain` binary for `run lead`, the full command tree, every owner module's entry point, and the Rust test sandbox.
</objective>

- Executor = agy, through GSD execute-phase (D-01). No network: every cargo command uses `--offline --locked`. Do not edit 03-03's files other than runner.rs and stream.rs (both extended here, existing items unchanged) and lib.rs (module declarations).
- Ownership after this plan (wave 4 runs in parallel only because of it): 03-05 owns projects.rs, routing.rs, profile.rs, config.rs; 03-06 owns planfile.rs; 03-07 owns stream.rs, term.rs, guard.rs; 03-08 owns fastpath.rs, stats.rs; 03-09 owns procs.rs, runner.rs; 03-10 owns roles/mod.rs and roles/lead.rs; 03-11 owns roles/dev.rs and roles/qa.rs. Nobody after this plan edits lib.rs, main.rs, app.rs, db.rs, tasks.rs, gitops.rs or tests/common/mod.rs, so main.rs (full command tree) and tests/common/mod.rs (full Sandbox API) get their final shape here.
- Entry points owned by later plans return `Err(BrainError::not_available("<command>"))` — the same "chưa có trong bản cài này" behaviour brain/cli.py has for unknown handlers. `guard` instead exits 2 (fail-closed) with stderr `agent-brain guard: chưa có trong bản này — chặn (fail-closed)`.
- User-facing strings use the program name `agent-brain` (orchestrator decision 3); everything else is byte-identical to the Python messages named in each step.
