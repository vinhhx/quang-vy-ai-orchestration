<objective>
Close gap G-07-NOPUSH-THEN-PUSH found by plan 07-08: after `agent-brain journal export --no-push`, the next `agent-brain journal export` commits nothing and prints "không có thay đổi", because `commit_and_push` stages only the paths that THIS run's writer changed, and the files written by the earlier `--no-push` run are already identical on disk. That is the documented first-run flow (D-22: review the diff with `--no-push`, then push), so the vault would stay empty.

Root cause (verified by reading the code): `mod.rs::export_with_tz` builds `paths = written.changed + written.removed` from `writer::apply`, which compares against the files on disk, not against git. Tracked modified files are restored from HEAD by `gitsync::check_dirty` at the start of the next run, so they are rewritten and reported as changed; UNTRACKED new files (status ignores them: `--untracked-files=no`) stay on disk, are reported unchanged and are never staged.

Fix (minimal, no signature change of `commit_and_push`): a new `gitsync::pending_paths` lists the generated paths that git sees as untracked or different from HEAD; `export_with_tz` unions them into `paths` (and into `report.changed`) before `commit_and_push`.

- Task 1: tests that reproduce the bug (RED) and pin the intended behaviour.
- Task 2: implement `pending_paths` and use it.
- Task 3: make the live-check script and README use the real same-clone flow (remove the 07-08 workaround).
</objective>
