# Plan 06.2-03: let a pinned-account engine run on work projects and let QA use it

Phase 06.2, plan 3. Explicit user decision (2026-10-28): the default `claude` account and `agy` are both out of quota; the user wants one team that runs every role, including QA, on `claude-max`, on work and personal projects. This deliberately relaxes two earlier decisions, which this plan amends:
- **D-36 / D-38 (amend):** a pinned engine used to be restricted to its pinned profile. Now an explicit `allowed_profiles` on a pinned engine wins over the implicit restriction. The pin keeps choosing the ACCOUNT (`CLAUDE_CONFIG_DIR`), `allowed_profiles` chooses where it may run.
- **D-39 (amend):** QA used to be strictly the built-in `claude`. Now QA may be the built-in `claude` OR an engine of kind `anthropic` with NO `base_url` (a Claude CLI account/profile variant, such as `claude-max`). Third-party endpoints (an `anthropic` entry with `base_url`), `agy`, `dsh` and people stay forbidden for QA.

Default behaviour must not change for anyone who does not opt in: a pinned engine without `allowed_profiles` is still restricted to its pin; QA with anything else stays refused.

## Required behaviour
1. `allowed_profiles` together with `pin_profile`: the effective restriction is the explicit `allowed_profiles` list (the pin still selects the account/`CLAUDE_CONFIG_DIR`). Without `allowed_profiles` the effective restriction stays `[pin_profile]`. Validate values (`work` / `personal` only, non-empty) with the existing error style; a pinned engine with `allowed_profiles` that omits the pin is accepted (document it).
2. The profile guard (every bind point and the run-seam backstop) uses `effective_allowed_profiles()` unchanged, so a pinned engine with `allowed_profiles: ["work","personal"]` is accepted on work projects at all of them, and a pinned engine without it is still refused with the exact existing D-36 text.
3. A run of such an engine on a work project must still set the PINNED profile's `CLAUDE_CONFIG_DIR` (the account), not the project's. Prove it with a test using the fake claude (the env the engine plan builds for a work project contains the pinned dir).
4. QA rule: allowed engines for `qa` are `claude` and any named engine whose kind is `anthropic` and which has no `base_url`. Refusal text for anything else: `QA chỉ dùng engine claude hoặc một engine anthropic không có base_url (tài khoản Claude khác).` Update every place the old text or rule appears (validator, Settings team editor select, tests) consistently; QA readiness/`chưa kiểm`/profile guard apply to the chosen QA engine like any other role.
5. Settings team editor: the QA select offers `claude` and the configured anthropic engines without `base_url`; a not-ready option reads `{id} — {word}` like the other selects.
