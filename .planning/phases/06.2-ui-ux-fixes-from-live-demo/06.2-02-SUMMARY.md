# Phase 06.2 Plan 02: Telegram menu with bot info and status Summary

A read-only "Telegram" screen in the dashboard sidebar backed by `GET /api/telegram`, showing whether the bot is off, misconfigured, starting, running or disconnected, with bot name, paired chat, outbox size, daily task count, config path and a setup hint when off; it polls every 5 s and never exposes the token.

## What was built

- `telegram/status.rs`: process-global `OnceLock<Mutex<..>>` store (states `off|error|starting|running|degraded`), with a redaction list (token and its secret half) used to scrub failure messages before they are stored. Seven unit tests on a local `Store` (no global state).
- `telegram/mod.rs`: `start` sets `off` (missing file), `error` (insecure/invalid file, api-base or curl check failure, thread spawn failure) or `starting`; `poll_thread` sets the bot username on the first `getMe` and `error` on 401 or a non-retriable failure; `Health::failed/ok/ok_quiet` feed `degraded`, recovery and `last_ok_at`. Bot behaviour (polling, outbox, detector, intake, callbacks) is unchanged.
- `dashboard/api_telegram.rs`: `GET /api/telegram`, always 200, behind the existing token gate. Adds `tasks_today` (same `count_tasks_since` + `local_midnight_ms` the OD-2 cap uses; `null` if the DB cannot be read), `tasks_per_day_limit` and `config_path`. Outbox size is read live through a `Weak<BotCtx>` probe.
- Screen: `screens/telegram.html`, `js/telegram.js`, nav link after Cai dat, route and title in `app.js`, two `ASSETS` entries, rebuilt `app.css`. Badge reuses `AB.stepClass/stepGlyph` so colours match the readiness badges in Cai dat. Alert text is the server message verbatim (rose for error, amber for degraded). Polling uses `AB.every`, which the router clears on route change; the existing connection-lost banner works unchanged because the fetch goes through `AB.api`.
- `dashboard-js-check.mjs`: new `telegram` section (badge word and colour per state, rows hidden without data, limit 0 reading, verbatim message, planted token never rendered, 5 s timer registered and cleared, failure/recovery/stale behaviour, markup has no input/form/token/x-model/x-html/style, nav link, route and title). 
- `dashboard-smoke.sh`: `telegram` screen asserting the `off` state in the DOM (badge, exact off sentence, command text, only the `config` row with the sandbox path, no input/form, nav link current).
