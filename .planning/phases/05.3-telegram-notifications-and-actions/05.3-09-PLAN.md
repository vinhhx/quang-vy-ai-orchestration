Close gap G-01 from the 05.3-08 live check (`protocol-log/nghiem-thu-p5-3.md`, row P5.3-04; `05.3-08-SUMMARY.md`).

Bug: `Chạy thêm 1 vòng` always adds 1 to `grants[loop]`. The cap for a loop is `max_rounds + grant` (`autopilot/decide.rs`, e.g. the `review:revise` branch: `if r >= cap { Stopped(HetVong) }`). Trả về Lead (replan) may run a plan round past the cap without a grant (live: round 4 with cap 3, stop `round 4, cap 3`). A following `Chạy thêm 1 vòng` then sets grant 1 → cap 4 → `4 >= 4` → stops again immediately, no run.

Fix: when granting, raise the cap to at least `stop.round + 1`: add `max(1, stop.round + 1 - stop.cap)` to the grant (fallback +1 when either is missing). For a normal stop (round == cap) this is +1, unchanged.
</objective>
