<objective>
Make Telegram trouble invisible to the work: when the network or the Bot API fails, notifications wait and retry quietly (5 → 60 s backoff, 429 retry_after), stale ones are dropped, one warning line is printed per outage, and agents, autopilot and the dashboard never wait (D-05).

- Task 1 (tracer): a gate reached during a 502 outage is delivered exactly once after recovery, with one warning and one recovery line.
- Task 2: the outbox `Edit` / `Keyboard` items that plan 05.3-06 pushes (moved here from plan 05.3-03, which owned outbox.rs at the context limit) and the two-tasks-at-once notification test.
- Task 3: 429 retry_after, non-retryable 4xx, stale drop after an outage, the queue cap, and a full autopilot run that is not slowed by a persistent outage.

Purpose: D-05 — requirements TELE-03 (retry, queue, drop stale, one warning, never block) and TELE-05 (two tasks at once, each notified once).
Output: hardened `outbox.rs` with edit items, a retry_after cap in `transport.rs`, new `tests/telegram_outage.rs`, one more test in `tests/telegram_notify.rs`.
</objective>
