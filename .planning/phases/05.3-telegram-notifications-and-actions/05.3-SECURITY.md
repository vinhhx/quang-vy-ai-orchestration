> Per-phase security contract: threat register, accepted risks, and audit trail. ## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| agent-brain serve → api.telegram.org | outbound long polling and sends through the system `curl` | bot token (on curl stdin only), task titles, plan documents |
| Telegram updates → bot | messages and button presses from any chat reach `getUpdates` | untrusted text and callback data |
| bot → dashboard action functions | button presses run the same `run_control` / `run_task_action` / `kill_run` as the dashboard | approvals, re-plan notes, kills |
| `telegram.json` on disk → serve / setup | token and paired chat ID | secret |
| user terminal → `telegram setup` | token prompt and pairing code | secret |
| live check session → repository and user machine | real token and chat ID exist during the session; results are committed | secret, real processes |
