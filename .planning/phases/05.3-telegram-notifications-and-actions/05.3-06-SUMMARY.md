# Phase 05.3 Plan 06: Note for Trả về Lead, Kill with confirmation — Summary

**The button set is complete.**

- `Trả về Lead` asks for an optional note. The next text from the paired chat becomes the note; `Không ghi chú` or a 10-minute timeout sends it without one.
- `Kill` asks for a second confirmation before stopping the run, through the same `kill_run` the dashboard uses.
- Buttons on a tracked message refresh when the task moves on.

## Deviations

- **Executor:** a Claude `gsd-executor` subagent on `main`, in place of agy.
- **`return_lead_without_note` scenario:** it uses lead [plan, plan], not the plan's [plan, append]. Without a note the Lead re-plans from a fresh skeleton, so an append-only edit ends in `no_changes`. That is the dashboard's own behavior.
- **Kill test:**
  - It checks `Kill` plus the current rev on every button. While the dev run runs, the state offers no `Trả về Lead`.
  - It waits for the audit line, which can print after the edit lands.
- **Interfaces:** `on_kill(ctx, press, cb)` follows the code on `main`, not the plan's `cq` parameter.
- **Known gaps (by plan assumption):**
  - The registry is empty after a serve restart, so older messages are not edited.
  - If a run ends by itself while the Kill confirmation is showing, the confirmation line stays until the next edit. It cannot kill anything, because the confirm press re-checks rev and the running run.
  - Tasks whose project left the map (`Gone`) are not edited.
