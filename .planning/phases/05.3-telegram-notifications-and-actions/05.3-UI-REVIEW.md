# Phase 05.3 — UI Review

Surfaces audited: Telegram bot messages and inline buttons (`render.rs`, `bot.rs`), CLI output of `agent-brain telegram setup` (`setup.rs`). Code-only review; flows were not exercised by the auditor (UAT reports 3/3 passed).

## Pillar Scores

| Pillar | Score | Key finding |
|--------|-------|-------------|
| Copywriting | 3/4 | Consistent Vietnamese copy reusing 05.1/05.2 vocabulary (D-03); weak run-failed text and `UNAVAILABLE_TEXT` |
| Visuals (message layout) | 2/4 | Plain undifferentiated lines, no headline emphasis, one button per row |
| Color | N/A | Plain text; `parse_mode` deliberately off for injection safety |
| Typography | N/A | Same reason; `✓` / `«»` usage inconsistent (see Visuals) |
| Spacing | N/A | Only line breaks; length bounded by `MAX_TEXT` 3900 with `…` clipping |
| Experience Design | 3/4 | Strong stale-state re-checks, Kill confirm, note prompt with timeout, outage queue |

## Top Fixes (all WARNING)

1. **Run-failed message gives no reason** — `render.rs` ~L255. Add outcome/exit and last error line (~200 chars) and name where the log is.
2. **`Dừng hẳn` has no confirmation** — `bot.rs` L464 (`auto_end`). Reuse the Kill confirm pattern; resuming needs the dashboard (`bot.rs` L1018).
3. **No visual headline** — `render.rs` `text_for`. Add a one-glyph status prefix per event (⏸ gate, ⛔ stop, ✅ QA, ❌ failed); emoji keep `parse_mode` off.
4. **Inconsistent result marker** — `render.rs` `result_suffix`. Same marker/structure for Telegram vs. elsewhere actions.
5. **Copy clarity** — `bot.rs` L41 `UNAVAILABLE_TEXT` doesn't say what happened or what to do; pick one convention for untranslated terms (`Kill`, `run`, `task`, `profile`).
6. **QA-passed dead end and tall keyboards** — `render.rs` `buttons_for` `QaPass => {}`. Add a next-step line; put short buttons on one row.

## Minor

7. CLI strings in `setup.rs` (L128, L176, L204) are good — name the problem and next command; pairing prompt states its 10-minute expiry. Keep this tone in Telegram strings.
