## Warnings

### WR-01: `find_plan_commit` scans the whole history and can pick a commit that is not this task's

**File:** `agent-brain/src/dashboard/api_tasks.rs:764-779` (called from 809, 880 and 1210)
**Issue:** `git log --format=%H %s <branch>` has three problems.
1. It walks the entire reachable history on every call. That is every 3 s per open task tab, plus the `get_task` poll. It spawns a full `git log` each time and never stops at the branch point.
2. It returns the newest commit anywhere in the history whose subject equals `{slug}: plan`. That includes commits that came from the base branch. If a slug is reused after the earlier task was merged and its branch deleted, an old merged plan commit is returned when the new plan is not yet committed. `is_ancestor(old_plan, dev_base)` is then true for every new Dev run. The gate shows "đã duyệt plan" with no plan on this task. `upsert_task` keeps the same task row, so old runs stay attached too.
3. A bare `<branch>` resolves tags before heads (`refs/tags/task/x` wins), and it is ambiguous if a path with that name exists in the work tree. The ambiguity makes `git` fail, which is silently downgraded to `PlanFacts::Unknown`. There is no `--` separator.

**Fix:** Bound the range to the branch's own commits, use a full ref, and stop the revision walk with `--`:
```rust
let reff = format!("refs/heads/{}", task.branch);
let mut args = vec!["log", "--format=%H %s", "--topo-order"];
let range;
if let Some(b) = task.base_commit.as_deref().filter(|b| crate::gitops::is_hex_sha(b)) {
    range = format!("{b}..{reff}");
    args.push(&range);
} else {
    args.push(&reff);
}
args.push("--");
```
Make `is_hex_sha` `pub(crate)`. Keep the `starts_with('-')` guard.

### WR-02: `is_ancestor` treats git errors as "not an ancestor", so the gate can flip on a transient failure

**File:** `agent-brain/src/gitops.rs:113-119` (used by `agent-brain/src/dashboard/pipeline.rs:622` and `agent-brain/src/dashboard/api_tasks.rs:814`)
**Issue:** `git(...).is_ok()` is false both for exit code 1 (genuinely not an ancestor) and for exit 128 (missing object, index.lock, spawn failure, unresolvable SHA). On any error `approving_dev_run` returns `None`, so `PlanFacts::Commit { approved_by: None }` is produced. The Bạn card flips from `xong` to `chờ bạn`. `current` moves the ring from Code to Bạn. The ledger header shows a contradictory state. The next poll flips it back. The spec says unknown must be shown as unknown, not as a negative result.
**Fix:** Return a tri-state and propagate it:
```rust
pub fn is_ancestor(root: &Path, a: &str, d: &str) -> Option<bool> {
    if !is_hex_sha(a) || !is_hex_sha(d) { return None; }
    let st = Command::new("git").args(["merge-base","--is-ancestor",a,d])
        .current_dir(root).env("GIT_TERMINAL_PROMPT","0").status().ok()?;
    match st.code() { Some(0) => Some(true), Some(1) => Some(false), _ => None }
}
```
Make `approving_dev_run` return `Result<Option<i64>, ()>`, and map `Err` to `PlanFacts::Unknown` in `plan_facts`.

### WR-03: Plan "chờ bạn" and the Bạn gate accept a Lead run whose verdict is a failure

**File:** `agent-brain/src/dashboard/pipeline.rs:283-290`, `421-431` and `440-463`
**Issue:** The "chờ bạn" header (R9) tests `last_run.status == "succeeded"`. `latest_succeeded_lead` in `derive_ban_card` tests the same. A Lead run with `status = succeeded` and `outcome = protocol_violation` (or `dev:blocked` or `qa:fix`) passes both tests. The ledger row for that run reads "vi phạm giao thức" and the Lên plan card agrees. The plan group header still says "chờ bạn", and in the `Unknown` path the Bạn card says "chờ duyệt plan" in amber. A protocol-violating Lead does not hand a plan to the user, so the UI contradicts itself. The `Commit` path is less affected, because it keys off the git commit.
**Fix:** Use the derived verdict instead of the raw status, in both places:
```rust
fn lead_ok(r: &RunRow) -> bool { taskstate::step_state(Some(r)).0 == "xong" }
// R9:            ... && lead_ok(last_run) && !dev_after
// derive_ban_card: .filter(|r| r.role == "lead" && lead_ok(r))
```

### WR-04: `loadPipeline` can stay "busy" forever, and the sequence guard is dead code

**File:** `agent-brain/assets/dashboard/js/task.js:109-152`
**Issue:** `_pipeBusy` blocks any second request until the first settles, and `AB.api` has no timeout or abort. If a pipeline request hangs (for example a stuck `git` call on the server), `_pipeBusy` never clears. Every later poll, SSE refetch and post-action refetch only sets `_pipeAgain`. The pipeline freezes with no stale indicator, because `pipeStale` is set only on a settled failure.

Because requests never overlap, `seq !== _pipeSeq` can only happen after `onLeave`. The "stale response discarded" check in `dashboard-js-check.mjs:686-698` simulates it by manually bumping `_pipeSeq`. The guard does not protect against the race its name suggests.

**Fix:** Let a request that has been busy too long be superseded, so the seq guard has a purpose:
```js
if (this._pipeBusy && Date.now() - this._pipeStarted < 10000) { this._pipeAgain = true; return; }
this._pipeBusy = true; this._pipeStarted = Date.now();
var seq = ++this._pipeSeq;
// finish(): only clear _pipeBusy / honour _pipeAgain when seq === self._pipeSeq
```
Also set `pipeStale = true` when a request exceeds the timeout.

### WR-05: Layout failure message never interpolates the width or the widest element

**File:** `scripts/dashboard-keys.mjs:398`
**Issue:** `` `LỖI layout: \${width}px trang bị tràn ngang (phần tử rộng nhất: \${info.widest})` `` is a template literal with escaped `\$`. It prints the literal text `${width}px ... ${info.widest}`. This is the only diagnostic that says which element overflowed the page, and it is lost exactly when the check fails.
**Fix:** Remove the backslashes:
```js
throw new Error(`LỖI layout: ${width}px trang bị tràn ngang (phần tử rộng nhất: ${info.widest})`);
```
The `\\s+` inside the `evaluate()` template (line 381) is correct. Leave it.

### IN-01: Duration and cost rules are duplicated three times

**File:** `agent-brain/src/dashboard/pipeline.rs:165-178` (ledger row), `496-511` (`derive_role_card`); also `agent-brain/src/dashboard/taskstate.rs:90-96` (`make_step`)
**Issue:** The same "running means now minus start, else ended minus start" and "killed or running or non-result source means unknown cost" logic exists in three places. Drift between the ledger and the cards is a likely future bug. Clippy also flags `manual_map` on both pipeline copies.
**Fix:** Add `fn run_duration(r, now) -> Option<i64>` and `fn run_cost(r) -> Option<f64>`. Build role-card sums from the already computed `ledger_rows` by role.

### IN-02: Clippy warnings introduced by this phase

**File:** `agent-brain/src/dashboard/pipeline.rs:421-424`, `440-443`, `523-528` (`double_ended_iterator_last`); `167` and `498` (`manual_map`)
**Issue:** `.filter(..).last()` iterates the whole iterator. `.rev().find(..)` or `.next_back()` is the idiom.
**Fix:** Replace `.last()` with `.rev().next()` on the filtered iterators.

### IN-03: Role-card cost is a partial sum with no signal

**File:** `agent-brain/src/dashboard/pipeline.rs:508-511`
**Issue:** If a role has one killed run (cost unknown) and one normal run, the card shows only the normal run's cost, for example `$1.00`. The ledger total carries a "Chưa tính chi phí của k run" note (spec A8), but the card does not. The card understates cost without saying so.
**Fix:** Add `cost_unknown: i64` to `RoleCard` and render `$1.00+`, or a `title`, when it is greater than 0. Or document that the card sums known runs only.

### IN-04: Test gaps on behaviour this phase claims to cover

**File:** `agent-brain/tests/dashboard_pipeline.rs`; `scripts/dashboard-keys.mjs:195-255`; `agent-brain/assets/dashboard/js/task.js:961-979`
**Issue:**
- No test exercises the 500 path of `get_pipeline`, which is where "no internal error text" is promised. The 500 assertion is missing.

For Kill and relead the trigger then disappears from the action list. `focusLater` polls for 1 s and falls back to `#screen`. `focus()` has no `preventScroll`, so the page can jump to the top. **Fix:**

### IN-05: `current_step` derivation and the strip caption duplicate mapping, and rely on `GitFacts::default()`

**File:** `agent-brain/src/dashboard/api_tasks.rs:1106-1115`; `agent-brain/assets/dashboard/js/task.js:888-898`
**Issue:** `get_pipeline` calls `taskstate::derive` with `GitFacts::default()` and `busy: None` only to read `current_step`. It also builds the action list and busy checks, and discards them. Today `current_step` depends only on the task status and running roles, so the result matches `get_task`. If it ever starts using git facts, the pipeline ring and the action caption (which falls back to a local copy of the mapping when `pipe.current` is null) would diverge silently.
**Fix:** Expose `taskstate::current_step(task, lead, dev, qa)` as a function and call it from both endpoints. Keep the JS fallback, but add a comment that it mirrors `pipeline::derive` R15.

### IN-06: `openStream` leaves the previous run's `streamRun` when the new run is not in `task.runs`

**File:** `agent-brain/assets/dashboard/js/task.js:170-181`
**Issue:** `streamRun` is assigned only when the run is found in `this.task.runs`. If a freshly started run is not in the last task payload, the previous run's `{role, status}` persists. `streamLine`, which is `aria-live`, announces the wrong role and status. The SSE `status` handler compares against that stale `prev` and can trigger a spurious pipeline refetch.
**Fix:** Set `this.streamRun = null;` before the lookup loop.
