<decisions>
## Implementation Decisions (locked)

### Scope and data
- **D-01:** Data comes only from existing `runs`/`tasks` rows and the git facts already used by the task screen. No schema migration, no new role, no protocol change.
- **D-02:** A "round" = the Nth run of the same role (lead / dev / qa) within the task, in start order. Round label "vòng N" (no cap shown in 5.1 because caps don't exist yet; show "vòng N" only, or "vòng N / 3" is NOT allowed — caps arrive with workflows in phase B).
- **D-03:** The "Bạn" gate card is **derived**: "chờ bạn" when the plan is committed and no Dev run exists on the current plan commit; "đã duyệt" + time when a Dev run started on the current plan commit (time = that Dev run's start). No new approval record/table.
- **D-04:** Stages that do not exist yet (Review plan, Review code, Sửa, PR nháp) are shown as **"chưa tự động"** (dashed, muted) — never faked with data. Researcher/UI-SPEC decides whether they render as placeholder cards inside the loop groups or as a single compact row; they must not look like real completed stages.
- **D-05:** Ledger lists every run of the task in start order, grouped by cycle headers (plan / build / QA, and a new cycle when Lead is re-run after Dev/QA), each row: round + role label, verdict word (from `runs.outcome`/`status`: e.g. qa:pass → "đạt", qa:fix → "cần sửa", dev:blocked → "vướng mắc", killed → "đã dừng", running → "đang chạy"), turns (`num_turns`), minutes (`ended_at - started_at`, live for running), cost (`cost_usd`; killed / usage_source≠result → "—" as Phase 5 UI-01 does). Total row: "N lượt chạy claude · M phút · $X". Clicking a row selects that run's log in the existing log pane.
- **D-06:** New endpoint `GET /api/tasks/{id}/pipeline` (token-gated like all routes) returns cards + ledger + totals; the screen keeps using SSE for live updates (no new transport).

### Design system (extends 05-UI-SPEC.md, does not replace it)
- **D-07:** Same stack and rules as Phase 5: Tailwind v4 standalone build (`scripts/build-css.sh`), Alpine CSP build (no inline expressions beyond what CSP build allows, object-form `:style`), no CDN, offline, Vietnamese copy, light + dark themes, 05-UI-SPEC spacing / typography (4 sizes, 2 weights) and banned-class list, `dashboard-ui-lint.sh` must keep passing.
- **D-08:** Status vocabulary (color + glyph + word, never color alone): xong ✓ emerald; **đang chạy ◐ blue** (changed from indigo — indigo is reserved for actions/selection); chờ bạn ● amber; đã dừng / lỗi ■ rose; chưa bắt đầu ◌ dashed slate; chưa tự động ◌ dashed, muted. The existing status chips elsewhere must be updated to blue for "đang chạy" consistently (Tổng quan, task screen) — one vocabulary.
- **D-09:** Stage connector arrows must meet contrast (fixes UI-REVIEW item: `text-slate-400` → slate-600 / dark slate-400).
- **D-10:** Below 640 px the pipeline stacks vertically (as the Phase 5 stepper does, no arrows); 640–1024 px it may scroll horizontally inside its own container; page body never scrolls sideways.
- **D-11:** Existing task-screen behaviour stays: Kill, Chạy Dev, Chạy QA, Chạy lại Lead buttons and their busy/disabled reasons, confirmation dialogs, plan/QA read-only panes, live log with pause / "Về cuối (live)" / raw JSON. Action buttons sit with the current stage (UI-SPEC decides exact placement), not duplicated.

### Process
- **D-12:** Claude plans and reviews; agy executes (CLAUDE.md). agy runs with `--dangerously-skip-permissions` were approved for Phase 5; re-confirm or reuse per the user's standing approval before executing 5.1.
