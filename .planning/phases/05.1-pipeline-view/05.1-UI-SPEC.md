## What changes (summary)

1. New status vocabulary shared by pipeline, ledger, legend and the existing chips: `đang chạy` moves from indigo to **blue** (D-08).
2. The Lead / Dev / QA stepper card (`task.html` lines 36-113) is replaced by the **pipeline card**: five stage cards (Bắt đầu, Lên plan, Bạn, Code, QA), three loop groups, a gate card, a compact "chưa tự động" row, one action strip, and a legend.
3. The **Lịch sử run** card (`task.html` lines 224-262) is replaced by the **ledger card** (`Sổ lượt chạy`): cycle headers, one clickable row per run, a total row.
4. Connector arrows meet contrast (D-09). Stacking breakpoint moves from 768 px (`md`) to 640 px (`sm`) (D-10).
5. New endpoint `GET /api/tasks/{id}/pipeline` feeds the pipeline and ledger; the action strip keeps using the existing task-detail payload, so Kill and step buttons work even if the pipeline request fails.

Order of the task screen, top to bottom: header card, **pipeline card**, D-03 callouts (when applicable), **ledger card**, plan card, QA card (if a report exists), log card. The order follows the design reference: pipeline, ledger, then the existing panes.

## Spacing Scale

Same scale as 05-UI-SPEC (4 / 8 / 16 / 24 / 32 / 48 / 64). New usage:

| Token | Value | New usage in 5.1 |
|-------|-------|------------------|
| xs | 4px (`gap-1`) | Between the lines inside a stage card; between glyph and label in the legend |
| sm | 8px (`gap-2`, `p-2`) | Gap between flow items; padding of a loop group; vertical padding of ledger cycle headers |
| md | 16px (`p-4`, `px-4`, `gap-4`) | Stage card padding; ledger row horizontal padding; gap between ledger label and metrics |
| lg | 24px (`p-6`) | Pipeline card and ledger card padding (the Card recipe) |

Exceptions (explicit, nothing else is allowed): `min-h-12` on ledger rows and action buttons (48 px, as in Phase 5); `1px` `border` / `ring-1` hairlines and `ring-2` current marker; fixed component sizes `w-36` (144 px, stage card), `w-40` (160 px, loop group), `w-4` (16 px, connector), `w-6` (24 px, glyph) — all multiples of 4. The 12 px steps (`px-3`, `gap-3`, `p-3`, `py-3`) stay banned. The design reference uses 168 px cards and 8 / 12 px paddings; those are translated to the on-scale values above.

Width budget at a 1024 px viewport (the contract width for "fits without scrolling"): main content 976 px, pipeline card inner 928 px. Flow = 2 cards x 144 + 3 loop groups x 160 + 4 connectors x 16 + 8 gaps x 8 = 896 px. It fits at 1024 px and wider; below 1024 px the flow scrolls inside its own container (D-10).

## Typography

No new size and no new weight. Mapping of the new elements onto the four Phase 5 roles:

| Element | Size / weight | Classes |
|---------|---------------|---------|
| Pipeline card title, ledger card title | Heading 20 / 600 | `text-xl font-semibold leading-[1.2]` (Card title recipe) |
| Stage card title (`Lên plan`, `Code`, ...) | Body size at 600 (same role the contract already allows for buttons) | `text-base font-semibold leading-normal` |
| Stage card role tag (`lead`, `dev`, `qa`) | Label size at 400, mono, uppercase | `font-mono text-sm font-normal uppercase leading-normal text-slate-600 dark:text-slate-400` |
| Stage card result line | Secondary text (14 / 400) | `text-sm font-normal leading-normal text-slate-900 dark:text-slate-100` |
| Stage card metrics line (`7 phút · $2.73`, time) | Secondary text, mono, tabular | `font-mono text-sm font-normal leading-normal tabular-nums text-slate-600 dark:text-slate-400` |
| Loop footer (`⟲ vòng 2`) | Secondary text, mono, centered | `text-center font-mono text-sm font-normal leading-normal text-slate-600 dark:text-slate-400` |
| Ledger cycle header | Label 14 / 600 | `text-sm font-semibold leading-normal` |
| Ledger row label and metrics | Secondary text 14 / 400; verdict word 14 / 600 | `text-sm font-normal leading-normal` + `tabular-nums` on metrics |
| Ledger total row | Body size at 600 | `text-base font-semibold leading-normal tabular-nums` |
| Legend entries, action-strip caption | Label size | legend `text-sm font-normal leading-normal text-slate-600 dark:text-slate-400`; caption `text-sm font-semibold leading-normal` |

Number formats added (client formatters in `js/app.js`, next to `fmtDuration` / `fmtCost`, which stay for the log pane and other screens):
- Clock: `AB.fmtClock(ms)` → `HH:MM` for today, `DD/MM HH:MM` for older. Used for `Bắt đầu` and `Bạn`.
- Minutes: `AB.fmtMinutes(ms)` → `{M} phút` with `M = round(ms / 60000)`; `0 < ms < 30000` shows `< 1 phút`; unknown shows `—`. The total row rounds the **sum of milliseconds**, not the sum of rounded rows, so rows may not visibly add to the total by up to a minute. The exact duration (`AB.fmtDuration`) is in each row's `title`. [ASSUMED A7]
- Cost: `AB.fmtUsd(usd)` → `$` + 2 decimals with a dot (`$2.73`, consistent with the dot-decimal `≈ $0.1234` of Phase 5); `0 < usd < 0.005` shows `< $0.01`; unknown shows `—`.
- Turns: `{n} lượt`; unknown shows `—` (unit omitted).

Rules:
- Glyph and verdict text use the "Text" column on the card or row surface; card body text keeps `text-slate-900 dark:text-slate-100`, secondary lines `text-slate-600 dark:text-slate-400`. Never lower opacity on text (`opacity-*` is not used on any element that holds text), so the placeholder row stays at full contrast.
- `chưa bắt đầu` (white fill, darker dashed border, a real stage that has not run) and `chưa tự động` (no fill, lighter dashed border, a stage that does not exist yet) must be visibly different; both stay dashed and muted so neither can be mistaken for a completed stage (D-04).
- Amber is used for `chờ bạn`, `vướng mắc` and `cần sửa` alike; the word and glyph (● versus !) tell them apart.
- "đã dừng" is the user-facing word for a killed run on every screen. The server `label` stays `killed` (tests in `taskstate.rs` assert it); the client maps state `killed` → `đã dừng` (see Deltas, row 4). [ASSUMED A6]
- Contrast: text colors above are the 700 / 800 shades on white and the 300 shades on slate-800, all computed >= 4.5:1 from Tailwind's default hex values (not measured in a browser; UAT spot-check, carried from 05-UI-SPEC U9). Dashed placeholder borders are non-interactive decoration and are exempt from the 3:1 non-text rule; the `chưa bắt đầu` border uses the stronger shade anyway.

## Screen Contract — Chi tiết task (`#/task/ID`)

### Pipeline card (replaces the stepper card)

Card title row: `Pipeline` (Heading). Content, top to bottom:

1. **Flow** (inside the scroll container): `Bắt đầu` → `Lên plan` (loop group) → `Bạn` → `Code` (loop group) → `QA` (loop group). Four connectors between the five items, hidden below 640 px.
2. **Placeholder row** `Chưa tự động` (compact; see D-04 decision below).
3. **Action strip** (only when the task-detail payload has actions).
4. `messageText` (`aria-live="polite"`) and `doneText` exactly as in Phase 5.
5. **Legend**.

Layout by width:

| Width | Behaviour |
|-------|-----------|
| >= 1024 px | Flow on one row, no scrolling (896 px of 928 px) |
| 640-1023 px | Flow on one row, scrolls horizontally inside the flow container only; the page body never scrolls sideways (D-10) |
| < 640 px | Flow stacks vertically (`flex-col`), connectors hidden, cards and groups `w-full`; placeholder chips and legend wrap; ledger rows stack label over metrics |

**Stage card anatomy** (top to bottom): optional role tag (`lead` / `dev` / `qa`; none for Bắt đầu and Bạn); glyph + title; result line; metrics line. `Bắt đầu` and `Bạn` show a time instead of minutes and cost.

**Which card is current** (gets the indigo ring and `aria-current="step"`): the server's `current_step` maps `lead` → Lên plan, `qa` → QA, `dev` → Code; **except** when `current_step` is `dev` and the Bạn gate is `chờ bạn` (status `planned`), the ring is on Bạn, because the user's decision is the current step and `Chạy Dev` is how it is made. A task with no runs has no ring (as in Phase 5).

**Card states, result lines and metrics (exact copy).** The metrics of a role card are the **sums over every run of that role in the task**; the state and result line come from the latest run of that role in the **current cycle** (cycle rules under Ledger). If a role has runs only in earlier cycles (Lead was re-run after Dev / QA), its card shows state `chưa bắt đầu` with result `chưa bắt đầu` and still shows the summed metrics. [ASSUMED A2, A12]

| Card | State | Result line | Metrics line |
|------|-------|-------------|--------------|
| Bắt đầu | xong (always) | `bạn đã giao` | `{AB.fmtClock(task.created_at)}` |
| Lên plan | chưa bắt đầu / đang chạy / xong / đã dừng / lỗi | `chưa bắt đầu` / `đang lập plan` / `plan đã commit` / `đã dừng` / `Lead lỗi` | `{phút} · {chi phí}` or `—` when no run |
| Lên plan | protocol_violation | `vi phạm giao thức` (state đã dừng / lỗi, ■) | same |
| Bạn | chưa bắt đầu (no plan committed yet) | `chưa có plan` | `—` |
| Bạn | chờ bạn (plan committed, no Dev run on the current plan) | `chờ duyệt plan` | `từ {AB.fmtClock(...)}` |
| Bạn | xong (a Dev run started on the current plan commit) | `đã duyệt plan` | `{AB.fmtClock(start of that Dev run)}` |
| Code | chưa bắt đầu / đang chạy / xong / vướng mắc / đã dừng / lỗi / vi phạm giao thức | `chưa bắt đầu` / `đang code` / `{n} lượt` (`xong` when turns unknown) / `vướng mắc` / `đã dừng` / `Dev lỗi` / `vi phạm giao thức` | `{phút} · {chi phí}` or `—` |
| QA | chưa bắt đầu / đang chạy / xong (qa:pass) / cần sửa (qa:fix) / đã dừng / lỗi / vi phạm giao thức | `chưa bắt đầu` / `đang kiểm tra` / `đạt` / `cần sửa` / `đã dừng` / `QA lỗi` / `vi phạm giao thức` | `{phút} · {chi phí}` or `—` |

The `Bạn` card has `title` = `Cổng duyệt suy ra từ dữ liệu: Dev đã chạy trên bản plan hiện tại thì coi là đã duyệt.` (D-03: no approval record exists). It has no button of its own.

**Loop group** (Lên plan, Code, QA): the frame holds the one real card and a footer `⟲ vòng {N}` where N = number of runs of that role in the task (D-02: Nth run of the role, no cap). With N = 0 the footer reads `chưa chạy`. `vòng N / 3` and any cap text are not allowed (caps arrive with workflows in phase B). The frame is always drawn (also for N = 0 or 1) so the layout does not jump while a task progresses, and so phase B can add review cards inside it.

**Placeholder decision (D-04).** The four stages that do not exist yet are **not** cards in the flow and **not** inside the loop groups. They are one compact row under the flow: label `Chưa tự động` (Label style) then four dashed chips, in this order: `◌ Review plan · chưa tự động`, `◌ Review code · chưa tự động`, `◌ Sửa · chưa tự động`, `◌ PR nháp · chưa tự động`, followed by helper text `Các giai đoạn này chưa có trong giao thức hiện tại; dashboard không giả lập kết quả.` Reason: cards inside loop groups would sit next to real results, add four extra boxes to the stacked 480 px layout, and invite the reading that a review happened. Chips carry no result, time or cost and are not interactive. [ASSUMED A3]

**Action strip** (D-11: actions sit with the current stage, never duplicated):
- Rendered from `task.actions` of the existing task-detail payload (server order; first enabled action = primary, others secondary, Kill = destructive), **not** from the pipeline endpoint, so it works when `/pipeline` fails.
- Caption (Label style): `Bước hiện tại: {Lên plan | Bạn | Code | QA}` using the same current-card mapping as above.
- Buttons, per-button reason text under each (`aria-describedby`), `actionHelp` text, in-flight labels (`Đang giao...`, `Đang dừng...`), the Kill and Chạy lại Lead confirmation dialogs: identical to Phase 5 (markup of `task.html` lines 50-58 moves here once instead of three times).
- Hidden when there are no actions.

**Legend** (always all seven entries, in this order; glyph in state color + word): `✓ xong` · `◐ đang chạy` · `● chờ bạn` · `■ đã dừng / lỗi` · `◌ chưa bắt đầu` · `◌ chưa tự động` · `! vướng mắc / cần sửa`. The first six are the PIPE-04 vocabulary; the seventh keeps the two Phase 5 attention states legible. [ASSUMED A9]

### Ledger card (replaces Lịch sử run)

Title `Sổ lượt chạy` (Heading), helper `Chi phí là giá trị tương đương theo API, không phải hóa đơn` (existing static label), then cycle groups, then the total row.

**Rows.** One row per run of the task with role `lead`, `dev` or `qa` (runs with role `inspect` are never listed or counted), in start order (`started_at`, then `id`). Row, left: `Vòng {n} · {plan | code | QA}` where n = the run's position among runs of the same role in the whole task (D-02), then `: ` and the verdict word with glyph. Right: `{n} lượt · {phút} · {chi phí}`. Examples: `Vòng 1 · plan: ✓ xong` / `69 lượt · 7 phút · $2.73`; `Vòng 2 · QA: ◐ đang chạy` / `12 lượt · 1 phút · —`.

**Verdict words** (from `runs.status` / `runs.outcome`; the verdict word is the only colored text in a row):

| Source | Word | State color |
|--------|------|-------------|
| `status = running` | `đang chạy` | blue, ◐ pulsing |
| `outcome = qa:pass` | `đạt` | emerald, ✓ |
| `outcome = qa:fix` | `cần sửa` | amber, ! |
| `outcome = dev:blocked` | `vướng mắc` | amber, ! |
| `outcome = protocol_violation` | `vi phạm giao thức` | rose, ■ |
| `status = killed` | `đã dừng` | rose, ■ |
| `status in (failed, timed_out, lost)` | `lỗi` | rose, ■ |
| `status = succeeded`, no outcome above (lead, dev) | `xong` | emerald, ✓ |

Precedence: running, then the three outcomes above, then killed, then failed / timed_out / lost, then succeeded.

**Per-field unknowns.** `—` (unit omitted) for: cost of a run with `status = killed` or `usage_source` other than `result` (as Phase 5 UI-01); turns when `num_turns` is null; minutes when the run has neither `ended_at` nor `running` status. A running run's minutes are live: `now - started_at`, updated on each poll.

**Cycles and headers.** Walk the runs in order. A **group** is a maximal sequence of consecutive runs of the same role (`lead` → kind plan, `dev` → build, `qa` → QA). The **cycle number** starts at 1 and increases by 1 each time a Lead run follows a Dev or QA run (D-05: Lead re-run after Dev/QA). Header per group, left text:
- plan group, cycle 1: `Chu kỳ 1 · plan đầu tiên`; plan group, cycle k >= 2: `Chu kỳ {k} · plan lại`
- build group: `Chu kỳ {k} · build`
- QA group: `Chu kỳ {k} · QA`

Header right text (plan groups only): `bạn đã duyệt` when a Dev run follows that group inside the same cycle; `chờ bạn` when it is the latest plan group of the task, its last Lead run succeeded and no Dev run follows; otherwise empty. Build and QA headers have no right text. A QA → Dev → QA sequence therefore renders as four groups under one cycle number (build, QA, build, QA), each with its own header. Cycle headers are not buttons and not focusable.

**Total row.** Left `Tổng đến giờ`; right `{N} lượt chạy claude · {M} phút · ${X}` with N = number of listed runs (all statuses, including running and killed), M = `fmtMinutes` of the summed milliseconds, X = sum of the costs of the runs that show a cost (rows showing `—` add nothing). When at least one run shows `—` for cost, a helper line follows: `Chưa tính chi phí của {k} run bị dừng hoặc chưa có kết quả.` The row is hidden when the task has no runs. [ASSUMED A8]

**Long ledgers.** Show the latest 20 runs (newest cycles stay at the bottom, in start order); when more exist, a secondary button `Hiện thêm 20` sits above the first visible row and reveals the next 20 older runs per press (same pattern as Tổng quan `Hiện thêm 10`). The total row is always computed over every run. [User decision 2026-10-19]

**Selecting a run.** Each row is a `<button type="button">` (D-05). Click or Enter/Space selects that run's log in the existing log pane (same `selectRun` behaviour as the old `Xem log` button), marks the row `aria-current="true"` with the selected style, appends the visible text `Đang xem` in indigo link color after the verdict, and scrolls the log card into view (`scrollIntoView({ block: 'nearest' })`, never smooth). Focus stays on the row; the log card's stream status line is `aria-live="polite"` so assistive tech hears `run N · role · status`. The row's `title` carries the exact duration and the token figures the old table showed: `vào X · ra Y · cache R / W`. Default selection on load is unchanged from Phase 5 (the running run, else the latest).

### Live updates

The pipeline endpoint is refetched on the task-detail poll (every 3 s), immediately when the log stream of the shown run ends or changes status (SSE `end` / `status` event), and immediately after any action (as `reload` does today). Elapsed minutes of a running run therefore advance in steps of the poll, not per second (Phase 5 U7 carried). No new transport (D-06). While a request is in flight the last data stays on screen.
