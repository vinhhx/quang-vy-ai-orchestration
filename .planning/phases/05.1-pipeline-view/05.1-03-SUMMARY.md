# Phase 05.1 Plan 03: Bạn gate from plan-commit ancestry — Summary

**The "Bạn" card now follows git.** It reads `chờ bạn` once a plan commit exists. It reads `đã duyệt` when a Dev run started from that commit or from a descendant of it. A newer plan commit or a Lead re-run puts it back to `chờ bạn`, and an unreadable repo falls back to run order instead of erroring.

## What was built

- **`gitops`:**
  - `is_ancestor(root, ancestor, descendant)` runs `merge-base --is-ancestor`.
  - `commit_time_ms(root, sha)` reads the committer time.
  - Both reject non-hex SHAs before calling git.
- **`pipeline.rs`:** `approving_dev_run(runs, plan_sha, plan_at, is_ancestor)` returns the Dev run that approved the current plan. Git access is passed in as a closure, so it is unit-tested without a repo (6 `test_approving_*` tests).
- **`api_tasks.rs`:**
  - `find_plan_commit`, `plan_commit_of` and `plan_facts` replace the two duplicated lookups (WR-12 partial). `find_commit_by_subject`, which walks `HEAD`, is no longer used.
  - `get_pipeline` now passes real `PlanFacts`.
- **Tests:** `pipe03_*` (6) run real git flows: Lead → waiting, Dev → approved at the Dev start, a manual plan re-commit → waiting, a relead → cycle 2 waiting, plus the fallbacks for a missing branch and a missing project map.
