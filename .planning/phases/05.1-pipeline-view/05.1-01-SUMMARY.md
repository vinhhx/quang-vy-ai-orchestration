# Phase 05.1 Plan 01: Pipeline endpoint and derivation — Summary

**`GET /api/tasks/{id}/pipeline` now returns the five stage cards, the run ledger grouped by cycle and the total row, from one pure, unit-tested function over the existing `runs` rows.** The schema, the role protocol and the write routes are unchanged.

## What was built

- **`db::runs_for_task`.** Every run of a task, ordered by `started_at`, then `id`.
- **`dashboard/pipeline.rs`.** The contract types (`PlanFacts`, `PipelineFacts`, `PipelineView`, `Cards`, `PointCard`, `RoleCard`, `Ledger`, `LedgerGroup`, `LedgerRow`, `LedgerTotal`), plus `derive` (rules R1–R16) and `state_word`. States reuse `taskstate::step_state`.
- **Route and `get_pipeline` handler.** The route sits under the existing `auth::gate` and is GET only. An unknown task returns 404 `Không tìm thấy task {id}`. The 500 body is fixed text.
- **Tests:**
  - 16 unit tests (`pipeline::tests::test_*`) covering every rule, with byte-exact Vietnamese strings.
  - HTTP tests `pipe01_cards_rounds_and_cycles_match_db` (Lead → Dev → QA Cần sửa → re-Lead, against brain.db), `pipe02_ledger_totals_match_db` (seeded killed and partial runs, plus an inspect run that must stay excluded), `pipe05_route_shape_auth_and_404` and `pipe05_refetch_is_idempotent`.
