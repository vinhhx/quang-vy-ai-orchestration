## Top 3 Priority Fixes

1. **Bạn gate rationale is reachable only by mouse hover** — `task.html:94` puts the explanation (`Cổng duyệt suy ra từ dữ liệu...`) in `title` on a non-focusable `div`. Keyboard, touch and most screen-reader users never get it, and "Bạn" is the one card that looks like an approval but is derived. Fix: add a visible helper line (or an `sr-only` sentence inside the result paragraph) on the Bạn card, or a one-line note under the flow. Keep the `title` as a bonus.
2. **Token columns removed from the ledger are tooltip-only** (`task.js:1118-1124`, assumption A4 of the spec) — touch users lost input/output/cache figures that Phase 5 showed in a table. Fix: add a `<details>` disclosure per row, or a "Chi tiết token" toggle on the selected row. Do this if UAT confirms the loss matters; the spec flagged it.
3. **Run a browser contrast and layout pass in both themes** — the 4.5:1 claims (spec A10) are computed from hex values only. Capture 1024, 768 and 480 px in light and dark. Check the blue-900/20 and emerald-900/20 tints under `text-*-300`, the `ring-2` indigo marker on `bg-indigo-50`, and the dashed `chưa bắt đầu` vs `chưa tự động` difference. Until this is done the Color and Visuals scores cannot reach 4.

Minor:
- Stage card titles (`Lên plan`, `Code`, `QA`, `task.html:54,74,97,117,141`) are `<p>` elements. Heading semantics would let screen-reader users jump through stages. The spec recipe also says `title`, so low priority.
- `Đang tải...` renders twice while the pipeline loads (`task.html:39` and `:248`). Harmless and consistent with the contract, but noisy for a live reader.
- `pipeFailed` callout heading (`task.html:42`) is a `<p class="font-semibold">`, matching the Phase 5 refusal recipe. A real heading would be better.

## Detailed Findings

### Pillar 1: Copywriting (4/4)
- Checked verbatim against the contract: `Pipeline`, `Pipeline của task`, flow `aria-label`, role tags, `Chưa tự động` row and four chips plus helper (`task.html:159-181`), seven legend entries in contract order (`:201-230`), `Sổ lượt chạy` and helper, `Chưa có lượt chạy nào` plus body, `Hiện thêm 20`, `Tổng đến giờ`, `Đang xem`, `Không tải được pipeline` plus `Thử lại`, `Trang tự thử lại; nếu vẫn lỗi, kiểm tra terminal đang chạy agent-brain serve.` (`task.js:744`).
- Loop footer `⟲ vòng N` / `chưa chạy` (`task.js:860-864`); no `/ 3` cap text. Strip caption `Bước hiện tại: ...` (`task.js:878`).
- Old strings `Lịch sử run`, `Xem log` and `Chưa có run nào.` are gone from the task screen (grep of task.html lines 280-405 shows no match).
- Finding: the card result lines come from the server `c.result` with client fallbacks only for the empty case (`task.js:815-821`), so the exact per-state copy (`plan đã commit`, `chờ duyệt plan`, ...) is owned by `taskstate.rs`/pipeline handler and was not re-verified here beyond the smoke check.

### Pillar 2: Visuals (3/4)
- Focal structure matches the reference: five cards, three loop groups (`task.html:69,112,136`), connectors with `aria-hidden` and `sm:block` (`:66,90,109,133`), current ring `ring-2 ring-indigo-600` applied in one place (`task.js:791`). Glyphs are `aria-hidden` and fixed `w-6`.
- Placeholder chips are dashed, glyph plus word, outside the loop groups, as decided in D-04.
- Warning: gate rationale is tooltip-only (see fix 1).
- Warning: visual fidelity vs `05.1-DESIGN-REF.html` was not confirmed with a rendered capture.
- Deviation accepted in summary 05: `relative` on the flow scroll region so `sr-only` spans stay clipped. Harmless.

### Pillar 3: Color (3/4)
- `dang_chay` is blue everywhere (`app.js:7`); STATE_TEXT carries the 700/800/300 text shades (`app.js:30-40`); glyph map uses ■ / ◌ / ● per D-08.
- Indigo is confined to the allowed set: primary action fill (`task.js:914`, `dialogOkClass`), focus outline, current-card ring (`task.js:791`), selected ledger row (`task.js:1138`), nav (`app.js:513`), plus `assign.js:438` on another screen. No new indigo use found.
- No hardcoded hex or `rgb(` in screens/js. No `opacity-*` on text-bearing elements except `disabled:opacity-50` on buttons (a Phase 5 recipe).
- All required classes exist in `app.css`; `scripts/build-css.sh --check` reports `app.css khớp nguồn`. `w-36`/`w-40` appear only as `sm:w-36`/`sm:w-40`, which exist.
- Warning: contrast unmeasured in-browser (fix 3). Pre-existing amber `ring-2` on the plan/QA card (`task.js:582,1037`) competes with the indigo "current" ring semantics; not new in this phase.

### Pillar 4: Typography (4/4)
- Distribution across task.html + task.js + app.js: `text-sm` 64, `text-base` 23, `text-xl` 9, `text-2xl` 1; weights `font-normal` 54, `font-semibold` 45. No `text-xs`, `text-3xl`, `font-medium`, `font-bold`.
- Mono / `tabular-nums` used on metrics lines and ledger metrics; `leading-normal` on text; `leading-[1.2]` only on card titles (declared).
- The only arbitrary value is `lg:h-[32rem]` on the pre-existing log pane (`task.html:365`), not part of this phase.

### Pillar 5: Spacing (4/4)
- Values used: `gap-1/2/4`, `p-2`, `p-4`, `p-6`, `px-4`, `py-2`, `pt-4`, `pb-2`, `min-h-12`; no banned 12 px steps (banned-class grep returned nothing; `dashboard-ui-lint.sh`: `UI lint OK: 40 thẻ tương tác`).
- `w-36` cards, `w-40` groups, `w-4` connectors match the 896/928 px budget; below 1024 px the region scrolls (`overflow-x-auto pb-2`), below 640 px `flex-col` with `w-full` items.
- Smoke check reported no page-level overflow at the tested width (summary 05 notes a 768 px overflow found and fixed).

### Pillar 6: Experience Design (3/4)
- State coverage: loading (`pipeLoading`), first-load failure with retry (`pipeFailed`, `reloadPipeline`), stale line (`showStale`), empty ledger, per-field `—`, `Hiện thêm 20` paging, total row hidden with no runs.
- Action strip reads `task.actions`, so Kill and step buttons survive a `/pipeline` failure (`task.html:184-195`).
- Ledger rows are native buttons with `aria-current`, `Đang xem` marker, `scrollIntoView({block:'nearest'})` (`task.js:1143-1148`).
- Dialog focus return is implemented (`lastFocusId` then `focusLater`, `task.js:960-966`), closing the 05-UI-REVIEW carry-over finding. After Kill the trigger may be re-rendered away, so it falls back to the screen; acceptable.
- Warnings: tooltip-only gate text and token data (fixes 1, 2); interaction behaviour was not driven in a browser by this audit (smoke checks DOM only).
- Registry audit: skipped, shadcn not initialized (`Tool: none`).
