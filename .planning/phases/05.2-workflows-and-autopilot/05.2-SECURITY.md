## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| agent-brain → `brain.db` (several processes) | the v2 migration rewrites `runs`; serve, pump, CLI and driver open the DB concurrently | months of run/event history |
| user `config.json` / `workflows.json` / `projects_map.json` → agent-brain | hand-edited files set limits, prices, stages and project defaults | spend limits, workflow shape |
| LLM-written reports (`.plan-review.md`, `.code-review.md`, `.qa-report.md`) → agent-brain | verdict/counts drive the loop; named files widen fix-mode write access | prompt-injection-reachable text |
| reviewer / Dev (LLM) → repo working tree | reviewers read the whole repo and may write only their report; Dev writes under the guard | code, secrets on disk |
| autopilot driver → child `agent-brain run` → `claude` | the driver spends money and changes code by starting stages | argv, signals, PIDs |
| DB flags (stop, kill, approval) → driver | CLI kill and dashboard steer the driver through the DB | stop/kill/approval state |
| browser → `GET /api/workflows`, `POST /api/tasks`, six new POST control routes | untrusted JSON (project, request, name, workflow, note, rev) reaches child argv and approvals | behind the token gate |
| server JSON → DOM | strings derived from LLM reports, git and user files are rendered | display text |
| live checks → user accounts and data | real claude spend on the work profile | DB copy, private XDG dirs, port 7438 |

| W-1 | high (unverified at runtime) | Reviewer roles allow `Bash(git diff *)`, `Bash(git log *)` and `Bash(git show *)` (`review.rs:7-15`). The same rules exist in Lead and QA since Phase 3 (`36838c1`). git's `--output=<file>` diff option writes to any path. Cover Lead, QA and both review roles. |
