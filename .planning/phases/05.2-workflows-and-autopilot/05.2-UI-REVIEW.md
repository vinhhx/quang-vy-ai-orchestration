## Top 3 Priority Fixes

1. **Autopilot header contradicts itself at the gate (WARNING)** — the badge says `Autopilot: chờ bạn duyệt plan` while the only control is a disabled `Bật autopilot` (gate-1024.png, header). Users read "autopilot is off, and I cannot turn it on", and there is no `Dừng autopilot` while paused at the gate. Fix: while autopilot is active-and-gated, render `Dừng autopilot` (enabled, secondary) instead of a disabled `Bật autopilot`, keep the helper `Autopilot dừng ở bước duyệt plan — bấm Duyệt plan để chạy tiếp.`
2. **Two competing next actions at the gate (WARNING)** — the Bạn card offers `Duyệt plan` / `Trả về Lead`, and the action strip below (`Bước hiện tại: Bạn`) offers `Chạy Dev` / `Chạy lại Lead`. Under autopilot, `Chạy Dev` silently counts as approval but runs Dev manually; the user cannot tell which path keeps autopilot driving. Fix: when the workflow is `auto: true` and the gate is `chờ bạn`, hide `Chạy Dev`/`relead` from the strip (same exclusion rule the spec already applies to `approve`/`return_lead`), or add a helper `Chạy Dev tay sẽ bỏ qua autopilot cho bước này.`
3. **Plan "Thay đổi" table is unreadable on narrow widths (WARNING)** — `task.html:379` uses `break-all` on the File cell in an auto-layout table, so paths split per letter (`src/c alc.p y` at 1024, worse at 480). Fix: give the File column `whitespace-nowrap` with `overflow-x-auto` on the table wrapper, or switch to a stacked card list below `sm`.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- PASS: `Duyệt plan`, `Trả về Lead`, `chờ duyệt plan`, `từ 22:12`, `⟲ vòng 2 / 3`, `◌ PR nháp · chưa tự động`, placeholder helper, gate rationale `Autopilot dừng ở đây để bạn duyệt plan...` (spec line 262) and the Tổng quan hint (smoke assertion) all match verbatim.
- WARNING: `Bật autopilot` (disabled) beside an "Autopilot: ..." status badge — see Fix 1. Spec Row D only defines helpers for "running" and "off"; the "paused at gate" state has no contract copy, and the implementation filled it with a message under a misleading label.
- WARNING: ledger row `duyệt Đang xem` concatenates two labels without a separator (gate-1024.png, Số lượt chạy).

### Pillar 2: Visuals (3/4)
- PASS: loop groups stack two cards with the loop footer; Bạn card is the visual focal point (amber fill + indigo primary); dashed future cards are clearly secondary.
- WARNING: duplicate action areas at the gate (Fix 2) dilute the focal point; the strip's `Chạy Dev` is a full-size secondary sitting directly under the gate.
- WARNING: at 480 px the flow becomes one 7,241 px-tall column; the gate buttons are reachable but the plan and log push far below. Acceptable, but no collapse of finished cards.

### Pillar 3: Color (3/4)
- PASS: indigo only on `Duyệt plan` primary and the selected ledger row (spec line 146); stop/kill red not used for `Dừng` actions; dark theme keeps amber gate distinct (gate-1024-dark.png).
- WARNING: `Bật autopilot` disabled state is low-contrast grey on white in light theme; text contrast was not measured in either theme (same gap as 05.1).

### Pillar 4: Typography (4/4)
- Sizes: text-sm (150), text-base (63), text-xl (23), text-2xl (10). Weights: font-normal (126), font-semibold (119). Matches the contract; no banned classes.

### Pillar 5: Spacing (3/4)
- PASS: one arbitrary value only (`[32rem]`, pre-existing), `max-h-[60vh]` raw dialog unchanged; card gaps on scale.
- WARNING: plan table File column (Fix 3). Bạn card at 1024 is 112 px wide with `px-2` buttons as specified, but `Trả về Lead` is at the limit; any longer copy will wrap.

### Pillar 6: Experience Design (3/4)
- PASS: gate buttons, return dialog (focus return), stop banner, picker and layout-5.2 key checks pass in the smoke; loading/error states retained from 5.1.
- WARNING: no stop control while gated (Fix 1); manual path bypass ambiguity (Fix 2).
- WARNING (test harness race): `dashboard-smoke.sh:422` dumps the DOM with `--virtual-time-budget=6000 --dump-dom`. Virtual time does not wait for real network I/O, and `overview.js:40` fills the groups only after `AB.api('GET','/api/tasks?limit=100')` resolves. If the fresh serve answers slowly (first sqlite open, loaded CI host), the dump is taken before `loaded=true`, so the `waiting` group is empty/hidden and the assertion at `dashboard-smoke.sh:1004-1011` fails. This explains the one non-reproducible failure; it is a harness race, not a product bug. Fix: warm the endpoint with `curl` before launching Chrome, and/or retry the dump once when `data-overview-group` items are missing (or have overview set a `data-loaded` marker and poll for it).
- This run: smoke passed 1/1.
