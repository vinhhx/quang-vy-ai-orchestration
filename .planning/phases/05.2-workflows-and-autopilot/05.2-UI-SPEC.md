## What changes (summary)

1. **Pipeline flow is data-driven.** The five hard-coded cards become a list rendered from the task's workflow snapshot. Loop groups now hold **two stacked cards**: Lên plan + Review plan, Code + Review code, QA + Sửa. Three of the four 5.1 `chưa tự động` chips become real cards; only `PR nháp` stays a chip. Footer becomes `⟲ vòng N / cap`.
2. **New cards and verdict words.** Review plan, Review code, Sửa; verdicts `duyệt`, `đạt`, `sửa lại`; counts `chặn / góp ý` (reviews) and `kiểm thử / lỗi` (QA).
3. **Bạn card becomes a real gate** with `Duyệt plan` and `Trả về Lead` (optional-note dialog), plus a visible rationale line (fixes 05.1-UI-REVIEW fix 1).
4. **Autopilot control and status** in the pipeline card header: status badge, `Bật autopilot` / `Dừng autopilot`, workflow line, budget line.
5. **Stop banner** (amber) with reason, detail and three buttons; amber ring on the stopped loop group; reason line in Tổng quan's `Chờ bạn` group.
6. **Giao việc "Quy trình" picker** (radio list) and a **read-only workflow list** (card on `#/projects`), with `workflows.json` error display.
7. **Ledger** gets counts, new verdict words, loop-based cycle groups, and a visible token line on the selected row (fixes 05.1-UI-REVIEW fix 2).
8. New and changed endpoints the UI reads: `GET /api/workflows`, `POST /api/tasks/{id}/approve`, `/auto`, `/auto/stop`; pipeline and task-detail payload fields (see "Data the UI reads").

Order of the task screen, top to bottom: header card, **stop banner (only when autopilot stopped)**, pipeline card, D-03 callouts (suppressed when the stop banner shows the same cause), ledger card, plan card, QA card (if a report exists), log card.

Number formats (client, `js/app.js`; new ones next to `fmtMinutes` / `fmtUsd` of 05.1):
- Budget figures: `{M} / {B} phút` where M = `round(used_ms / 60000)` and B the limit as a plain integer; money `$X.XX / $Y.YY` (2 decimals, dot, same as `AB.fmtUsd`). When the used cost includes estimates the used figure is prefixed `≈ ` (U+2248 plus a space).
- Counts: `{n} chặn`, `{n} góp ý`, `{n} kiểm thử`, `{n} lỗi`, `{n} không tự động được`; numerals only, no plural logic. An **unknown** count is omitted, never shown as `0`; a **known zero** is shown (`0 chặn`).
- Rounds: `⟲ vòng {N} / {cap}`, numerals.

## Screen Contract — Chi tiết task (`#/task/ID`)

### Pipeline card header and status

Row A: `Pipeline` (Heading), autopilot badge, toggle button (`ml-auto`).
Row B (workflow line): `Quy trình: {name} · {summary}`; summary is the server string (grammar under "Workflow summary"). A task with no snapshot (created before 5.2): `Quy trình: chưa có (task tạo trước Phase 5.2) — chạy tay từng bước.` and it is drawn as a manual workflow with no review cards.
Row C (budget line, only when the task has a snapshot): `Ngân sách: {M} / {B} phút · {$X} / {$Y}`. When either figure is at least 80 % of its limit, ` · sắp hết` follows; at 100 % or more ` · đã hết`. When the used cost includes estimates (CONTEXT D-19), the figure is `≈ $X` and a helper line follows: `Gồm chi phí ước tính từ token cho {k} run bị dừng hoặc chưa có kết quả, nên có thể lớn hơn Tổng đến giờ.`
Row D: helper under the toggle while autopilot runs: `Run hiện tại chạy nốt rồi autopilot dừng. Muốn dừng ngay: Kill.` While autopilot is off and the button is enabled: `Giới hạn: {cap} vòng mỗi bước lặp, {B} phút hoặc ${Y} cho cả task. Autopilot luôn dừng ở bước bạn duyệt plan.` (the first sentence uses the workflow limits; for a workflow without loops: `Giới hạn: {B} phút hoặc ${Y} cho cả task. ...`).

`Bật autopilot` and `Dừng autopilot` are task-detail actions (ids `auto_start`, `auto_stop`) rendered in the header, **not** in the action strip, so they keep working when `/pipeline` fails. Disabled reasons come from the server verbatim, under the button (busy project, legacy task without a snapshot, run already in flight for `Dừng`). In flight: `Đang bật...` / `Đang dừng...`; after success the `messageText` line says `Đã bật autopilot.` / `Đã yêu cầu dừng autopilot — run hiện tại chạy nốt rồi dừng.` While the state is `đang dừng` the button is disabled with reason `Đang chờ run hiện tại chạy xong.`

### Flow (data-driven)

The flow is rendered from the pipeline payload's group list. Canonical order: `Bắt đầu` → plan group → `Bạn` → build group → QA group, each drawn only if the workflow has it, with a `→` connector between neighbours. Contents of a group are the cards the workflow lists for that loop:

| Group (`data-group`) | Cards (`data-card` key, title, role tag) | Footer |
|----------------------|------------------------------------------|--------|
| plan | `plan` Lên plan `lead`; `plan_review` Review plan `plan-review` | `⟲ vòng {N} / {cap}` |
| build | `code` Code `dev`; `code_review` Review code `code-review` | `⟲ vòng {N} / {cap}` |
| qa | `qa` QA `qa`; `fix` Sửa `dev · fix` | `⟲ vòng {N} / {cap}` |

- **Frame always drawn** for every group the workflow has, also with one card (as 5.1), so the layout does not jump.
- A workflow without the review or fix stage (`nhanh`, tasks created before 5.2) shows a group with the single author card and the 5.1 footer `⟲ vòng {N}` (numerals, no cap) or `chưa chạy`. A workflow that lists only some stages (for example a user workflow that lists only Review code) shows only those cards; the ol `aria-label` is built from the drawn titles: `Pipeline: {titles joined by ", "}`.
- Footer: `⟲ vòng {N} / {cap}` where N = round of the latest run in that loop in the current cycle (server `round`) and cap = the workflow's `max_rounds`; no run yet: `chưa chạy`. When the group is where autopilot stopped (`stopped_in`), a second footer line shows the reason word (`hết vòng` / `hết ngân sách` / `vi phạm giao thức` / `vướng mắc` / `dừng bởi bạn` / `run lỗi`) and the frame is amber (Color).
- **Current card** (indigo ring, `aria-current="step"`): exactly one, taken from the server's `current_card` (`plan`, `plan_review`, `ban`, `code`, `code_review`, `qa`, `fix`). It is the running stage; between stages while autopilot runs, the next stage; at the gate, `ban`; when autopilot stopped, the card of the stage that stopped. A task with no runs has no ring.
- Metrics of every role card = sums over all runs belonging to that card in the task (05.1 A2 carried). The Code card includes Dev runs made after a Review code `revise`; the Sửa card is Dev runs made after a QA `fix` (CONTEXT D-09 / D-11).

### Ledger changes

- **Grouping.** A group is a maximal run of consecutive runs of the same **loop** (server field per run: `plan` for Lead and Review plan, `build` for Dev implement, Dev fix after Review code and Review code, `qa` for QA and Dev fix after QA). Runs from before 5.2 (no `stage`) fall back to the 05.1 role grouping. The cycle number rule is unchanged (+1 each time a Lead run follows a build or QA group; review runs never start a cycle). A QA → Sửa → QA sequence is therefore one `Chu kỳ {k} · QA` group.
- **Row label**: `Vòng {n} · {kind}: {glyph} {verdict}` with n = the run's `round` in its loop for the cycle (05.1 position-among-role for runs without `round`) and kind one of `plan` · `review plan` · `code` · `sửa theo review` (Dev fix after Review code) · `review code` · `QA` · `sửa theo QA` (Dev fix after QA).
- **Verdict words**, added to the 05.1 precedence (running, then outcomes, then killed, then failed, then succeeded):

| Source | Word | State |
|--------|------|-------|
| `outcome = review:approve` | `duyệt` | emerald ✓ |
| `outcome = review:pass` | `đạt` | emerald ✓ |
| `outcome = review:revise` | `sửa lại` | amber ! |
| others | as 05.1 | as 05.1 |

- **Row metrics**: counts first, then the 05.1 figures: reviews `{b} chặn · {a} góp ý · {n} lượt · {M} phút · ${X}`; QA `{specs} kiểm thử · {failing} lỗi · {n} lượt · ...` (plus `{k} không tự động được` after `kiểm thử` when the report carries it); other rows unchanged. Unknown counts are omitted. Example: `Vòng 1 · review plan: ! sửa lại` / `1 chặn · 4 góp ý · 41 lượt · 2 phút · $1.32`.
- **Token line (fix for 05.1-UI-REVIEW fix 2).** The selected row shows a visible line under it: `Token: vào {X} · ra {Y} · cache {R} / {W}` (`AB.fmtNum`; unknown run figures `—`). The `title` tooltip stays as a bonus. Rows that are not selected show nothing extra.
