# Phase 05.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: `05.2-RESEARCH.md` § Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Rust built-in test harness (unit tests plus `tests/*.rs` integration with `Sandbox` and the fake claude), Node scripts for the front end, bash smoke with headless Chrome and CDP keys |
| **Config file** | `agent-brain/Cargo.toml` (no separate test config) |
| **Quick run command** | `cargo test --manifest-path agent-brain/Cargo.toml --offline --locked <module-or---test-name>` |
| **Full suite command** | `cargo test --manifest-path agent-brain/Cargo.toml --offline --locked && node scripts/dashboard-js-check.mjs && bash scripts/dashboard-ui-lint.sh && bash scripts/build-css.sh --check` |
| **Estimated runtime** | about 26 s for cargo, about 60 s in total with the Node and lint gates; smoke with `--keys` adds about 60 s |

---

## Sampling Rate

- **After every task commit:** the narrowest `cargo test ... <module or --test name>` for the files touched, plus `cargo build --offline --locked` before any smoke run.
- **After every plan wave:** the full suite command above.
- **Before `/gsd-verify-work`:** the full suite is green, `bash scripts/dashboard-smoke.sh --keys overview assign task projects` is green, `build-css.sh --check` reports `app.css khớp nguồn`, and the AUTO-07 live checks are recorded.
- **Max feedback latency:** 120 seconds
