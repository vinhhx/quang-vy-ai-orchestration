# Phase 05.2 Plan 25: Bash git policy in the guard (W-1) — Summary

**A role can no longer write a file outside its allowed set through git.** A reviewer's `git diff --output=../leak-review.txt` is now blocked and writes nothing. The tracer test first confirmed that `--output` really does create the file when there's no guard.

## Deviations (stricter than the plan, all in the unit tables)

- **Unquoted globs are refused in git commands.** Bash expands them after the check, so a file named `--output=x` could smuggle in an option. Side effect: `git add src/*.py` is refused. Dev's fallback commit still covers that case.
- **Git behind a wrapper is refused.** If the first word is a wrapper (`env`, `timeout`, `sh -c`, `xargs`, `find`, `sudo`, …) and any later word contains "git", the call is refused. `git-<sub>` binaries are refused too. Side effect: `find . -name .gitignore` is refused.
- **Other tokenizer refusals:** control characters, a trailing backslash, and `X+=` / `X[i]=` assignment prefixes.
- **Commit options:** `git commit` also refuses `--pathspec-from-file`. The short options `c`, `C`, `u` and `S` end the scan of a short-option group, because they take a value.

## Open item (follow-up, not blocking)

- `git add -e/-p/-i` and a `git commit` without `-m` open an editor or prompt. With no terminal, the run hangs until its timeout. It writes nothing, so it isn't a security issue, but blocking those forms would save the timeout.
