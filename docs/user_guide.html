1. Tổng quan: agent-brain làm gì

agent-brain là bộ điều phối nhẹ, chạy bằng một file binary, dùng để giao việc cho AI agent (hiện tại là Claude Code CLI) trên các dự án của bạn. Nó thay thế bộ script Python brain cũ và dùng chung danh mục dự án với bộ script đó.

Giao thức và các vai trò

Mỗi task chạy theo một quy trình (workflow). Quy trình mặc định mac-dinh gồm ba vòng lặp và một cổng duyệt của bạn:

1. LeadĐọc yêu cầu, tạo nhánh task/<slug>, viết .plan.md và commit <slug>: plan. Chỉ được ghi .plan.md.
2. Review planĐọc toàn repo (chỉ đọc), ghi .plan-review.md: approve hoặc revise. Khi revise, Lead sửa plan theo báo cáo (vòng 2, 3…).
3. Bạn duyệt planAutopilot luôn dừng ở đây. Bạn bấm Duyệt plan, hoặc Trả về Lead kèm ghi chú.
4. Dev (Code)Sửa đúng các file trong bảng Thay đổi của plan. Sửa file ngoài danh sách là vi phạm giao thức (mã thoát 3).
5. Review codeĐọc diff từ commit plan, ghi .code-review.md: pass hoặc revise. Khi revise, Dev sửa theo báo cáo.
6. QAKiểm tra git diff, ghi .qa-report.md: Đạt hoặc Cần sửa. Không sửa code.
7. SửaDev ở chế độ sửa theo báo cáo QA, rồi QA chạy lại.

Sau khi QA Đạt, bạn tự review và merge nhánh task/<slug>. agent-brain không tự merge và không tự tạo PR (PR nháp · chưa tự động).

Chạy tay hay autopilot

CáchHành vi
Chạy tayBạn bấm hoặc gõ lệnh cho từng bước. Quy trình nhanh mặc định chạy tay: plan → Bạn → code → QA, không review.
Autopilotagent-brain tự chạy bước kế tiếp theo quy trình, trong giới hạn số vòng, phút và đô-la. Nó luôn dừng ở bước bạn duyệt plan. Khi chạm giới hạn hoặc gặp sự cố, nó dừng với một lý do bằng tiếng Việt và chờ bạn (mục 4.4).

Những đảm bảo chính

  • Đúng dự án (Fallback Ask): tên dự án khớp 0 hoặc nhiều hơn 1 dự án thì dừng và in danh sách để bạn chọn (mã thoát 2). Không bao giờ đoán.
  • Đúng nhánh: autopilot và lệnh duyệt có chạy tiếp từ chối chạy khi đang checkout nhánh của task khác (mục 4.5).
  • Kill sạch: mỗi lần chạy agent nằm trong process group riêng; kill dừng cả cây tiến trình con và cả autopilot của task, kiểm tra PID chưa bị tái sử dụng trước khi gửi tín hiệu.
  • Đo được token và chi phí: mọi sự kiện stream-json được lưu vào SQLite; stats, màn hình Thống kê và Sổ lượt chạy tổng hợp token và chi phí tương đương.
  • Hai tài khoản tách biệt: profile work (~/.claude) và personal (~/.claude-orca), gán theo dự án.

Hai cách dùng

CáchKhi nào dùng
CLI (agent-brain run …, auto, approve)Làm việc trong terminal, script hóa, chạy trên máy không có trình duyệt.
Dashboard (agent-brain serve)Xem pipeline và log trực tiếp, giao việc và chọn quy trình, duyệt plan, bật/dừng autopilot, bấm Kill, xem thống kê, sửa alias dự án. Chạy ngay trong binary, chỉ trên 127.0.0.1.

Hai cách dùng chung một cơ sở dữ liệu: run hoặc autopilot khởi chạy ở terminal hiện lên dashboard ngay, và có thể Kill từ dashboard.

Chi phí thực tế ghi nhận khi nghiệm thu Phase 5.2 (repo thử nghiệm nhỏ, Claude thật): một vòng mac-dinh đầy đủ có một lần sửa plan (7 run: Lead, Review plan, Lead, Review plan, Dev, Review code, QA) tốn khoảng $0.88–$1.02 (chi phí tương đương theo API). Task lớn hơn sẽ tốn hơn.

2. Cài đặt và kiểm tra

Yêu cầu

  • Linux x86_64. Binary là file tĩnh, không cần thư viện hay runtime nào khác.
  • Claude Code CLI (claude) đã đăng nhập cho profile bạn dùng. Cho profile personal: đăng nhập với CLAUDE_CONFIG_DIR=~/.claude-orca.
  • git trong PATH.
  • Trình duyệt bất kỳ (chỉ cần cho dashboard).

Cài binary

# Build từ mã nguồn (offline, khóa phiên bản)
bash scripts/build-release.sh

# Cài vào ~/.local/bin (thư mục này phải có trong PATH)
install -m 755 agent-brain/target/x86_64-unknown-linux-musl/release/agent-brain ~/.local/bin/agent-brain

# Kiểm tra
agent-brain --version        # agent-brain 0.1.0
agent-brain --help

Nếu máy không có musl-gcc, script build tự chuyển sang gcc và in cảnh báo; kết quả vẫn là binary tĩnh.

Lần đầu chạy bản 5.2 trên một brain.db cũ, cơ sở dữ liệu được nâng cấp tại chỗ (thêm cột quy trình, duyệt plan, autopilot) mà không mất dữ liệu. Task tạo trước Phase 5.2 vẫn xem được nhưng chạy tay như cũ (không có quy trình, không bật được autopilot).

Một config.json viết trước Phase 5.2 (không có khóa của hai vai trò review) vẫn dùng được: hai vai trò review nhận timeout 1200 và 1500 giây, model opus. Biến môi trường: AGENT_BRAIN_CONFIG (file cấu hình khác), AGENT_BRAIN_DB (database khác, tiện để thử nghiệm cách ly).

Mỗi task chạy theo một quy trình có tên. Có sẵn hai quy trình nhúng trong binary:

TênGiai đoạnTóm tắt (như dashboard hiện)Chạy
mac-dinhplan, plan-review, gate:you, implement, code-review, qa, fix — ba vòng lặpplan ⇄ review → Bạn → code ⇄ review → QA ⇄ sửa · 3 vòng · 60 phút · $20autopilot (auto: true)
nhanhplan, gate:you, implement, qaplan → Bạn → code → QA · 60 phút · $20chạy tay (auto: false)

Thêm hoặc ghi đè quy trình trong ~/.config/agent-brain/workflows.json (khi đặt XDG_CONFIG_HOME thì là $XDG_CONFIG_HOME/agent-brain/workflows.json; AGENT_BRAIN_CONFIG không đổi vị trí file này). File không bắt buộc, tối đa 256 KiB, được đọc lại mỗi lần cần (không phải khởi động lại serve). Dashboard chỉ xem; sửa bằng editor.

Ba khóa giới hạn không ghi thì lấy từ khóa autopilot của config.json. Khóa nào ngoài danh sách là lỗi. Tên quy trình: chữ thường, số và dấu gạch ngang, tối đa 40 ký tự.

Luật cổng duyệt: quy trình có plan hoặc plan-review mà còn bước sau (code, review code, QA, sửa) thì bắt buộc có gate:you. Không quy trình nào bỏ qua được bước bạn duyệt plan. gate:you cần có plan; fix cần có qa.

Ví dụ hợp lệ — thêm quy trình chi-phi-thap và rút ngắn nhanh (ghi đè theo tên phải ghi lại đủ stages):

{
  "chi-phi-thap": {
    "stages": ["plan", "plan-review", "gate:you", "implement", "qa"],
    "max_rounds": 2,
    "budget_usd": 3,
    "auto": true
  },
  "nhanh": {
    "stages": ["plan", "gate:you", "implement", "qa"],
    "budget_minutes": 30,
    "auto": false
  }
}

Kết quả: chi-phi-thap = plan ⇄ review → Bạn → code → QA · 2 vòng · 60 phút · $3; nhanh thành 30 phút · $20. Màn hình Dự án gắn nhãn từ workflows.json và ghi đè quy trình có sẵn.

Ví dụ không hợp lệ — bỏ bước duyệt và số vòng ngoài khoảng:

{
  "bo-qua-duyet": {
    "stages": ["plan", "implement", "qa"],
    "max_rounds": 0
  }
}

agent-brain bỏ riêng quy trình này và báo bằng tiếng Việt kèm số dòng:

Dòng 3: quy trình "bo-qua-duyet" phải có "gate:you" giữa bước plan và bước code/QA — autopilot luôn dừng ở bước bạn duyệt plan.
Dòng 4: "max_rounds" phải là số nguyên từ 1 đến 10.
  • File sai cú pháp JSON bị bỏ cả file: "Dòng L, cột C: workflows.json không phải JSON hợp lệ."
  • Một bản ghi đè sai thì quy trình có sẵn giữ nguyên. Hai quy trình mac-dinh và nhanh luôn dùng được.
  • run lead in mỗi lỗi thành dòng "Cảnh báo workflows.json: …"; Giao việc và Dự án hiện khung màu hổ phách "workflows.json có lỗi".

Chọn quy trình cho một task

Thứ tự ưu tiên: cờ --workflow (CLI) hoặc lựa chọn ở ô Quy trình trên Giao việc → workflow của dự án trong projects_map.json → mac-dinh.

  • Tên truyền qua --workflow mà không tồn tại: lệnh báo lỗi "Không có quy trình 'x' — các quy trình có: …", không tạo nhánh hay task.
  • Tên ghi ở dự án mà không tồn tại: dùng mac-dinh và báo "Quy trình 'x' của dự án không có trong workflows.json — dùng mac-dinh."
  • Bản sao theo task: khi tạo task, quy trình đã chọn (kèm giới hạn) được lưu cùng task. Sửa workflows.json sau đó không ảnh hưởng task đang có — kể cả khi bạn tăng ngân sách.

Ước tính = (input × giá input + output × giá output + cache_read × giá cache_read + cache_write × giá cache_write) / 1.000.000. Ghi đè từng họ trong config.json (phải đủ 4 số không âm); họ không ghi giữ giá mặc định. Model không khớp họ nào được tính theo họ đắt nhất để không vượt trần. Đây là bảng nhúng sẵn — hãy sửa nếu khác bảng giá bạn dùng.

Bước 2 — Bạn duyệt plan

  • Cần sửa plan: sửa bằng editor rồi commit. Plan có thay đổi chưa commit sẽ chặn bước Dev và lệnh duyệt.

Bước 3 — Dev thực hiện

  • Vi phạm giao thức (mã thoát 3): có file ngoài phạm vi bị sửa. Xem lại diff trước khi làm tiếp.

Bước 4 — QA kiểm tra

Cần sửa → chạy Dev ở chế độ sửa (--fix qa, mục 4.2) hoặc chạy lại Lead.

  • Luật nhánh: mọi bước autopilot và mọi lần duyệt có chạy tiếp cần đang checkout nhánh của task. 5. Lệnh nhanh, dừng tiến trình và thống kê

status — 0 token

agent-brain status "web bán hàng"

Không gọi Claude. Hiển thị trạng thái git, nhánh hiện tại, diffstat và run gần nhất trong database.

inspect — đọc nhanh diff

agent-brain inspect "web bán hàng" [--verbose]

Gọi Claude đúng 1 lượt, không công cụ, không lưu session. Diff lớn hơn inspect_max_diff_bytes (100.000 byte) được cắt gọn và có thông báo.

kill — dừng task (và autopilot)

agent-brain kill 12        # 12 là TASK_ID
  1. Nếu task có autopilot đang chạy, ghi yêu cầu dừng trước, để autopilot dừng với lý do dừng bởi bạn thay vì chạy bước kế tiếp.
  2. Đọc PID và thời điểm khởi tạo của run từ database, đối chiếu với /proc. Nếu PID đã bị hệ điều hành tái sử dụng, không gửi tín hiệu.
  3. Gửi SIGINT tới cả process group, chờ kill_grace_secs, rồi SIGKILL những tiến trình còn sót.
  4. Run được ghi killed; terminal đang chạy run đó thoát với mã 130, terminal đang chạy auto in "Autopilot dừng · dừng bởi bạn: …" và thoát 4.

Nếu autopilot đang ở giữa hai bước (không có run nào chạy), lệnh trả 0 với dòng "Đã yêu cầu autopilot dừng (task N) …".

Ở terminal đang chạy run: Ctrl+C một lần = dừng mềm; Ctrl+C hai lần nhanh = dừng ngay (dưới 1 giây). Đóng cửa sổ terminal cũng dừng cả cây tiến trình. Ở terminal auto: Ctrl+C dừng êm (mục 4.3).

Trạng thái kết thúc bất thường của run: killed (bị dừng có chủ đích), timed_out (quá thời gian), lost (tiến trình biến mất bất thường).

Báo cáo của Review plan, Review code và QA được tạo khung trước khi Claude chạy. Khi run đó lỗi, quá thời gian hoặc bị Kill, báo cáo được trả về như cũ và terminal in "Đã dọn <file> của lượt chạy không thành công.", để bước sau không bị chặn vì working tree bẩn. Báo cáo sai định dạng, báo cáo QA không có kết luận và run vi phạm giao thức thì giữ nguyên báo cáo làm bằng chứng (xem mục 10).

stats — token và chi phí

agent-brain stats
agent-brain stats --since 7d --profile work
agent-brain stats --since 24h --json      # JSON: total, by_project, by_role

--since nhận Nm, Nh, Nd (phút, giờ, ngày). Chi phí là giá trị tương đương theo API do Claude CLI báo trong kết quả của mỗi run — không phải hóa đơn thật. Run bị Kill hoặc chưa có kết quả không có số chi phí này (ngân sách autopilot ước tính riêng cho chúng, mục 3.5).

6. Dashboard web: khởi động và đăng nhập

Khởi động

agent-brain serve              # cổng 7437
agent-brain serve --port 8123  # cổng khác; --port 0 = hệ điều hành tự chọn

Terminal in một URL có token, dạng:

agent-brain dashboard: http://127.0.0.1:7437/?token=<64 ký tự hex>
  1. Mở đúng URL đó trong trình duyệt (dùng 127.0.0.1, không dùng localhost).
  2. Server đổi token thành cookie phiên và chuyển bạn về /; thanh địa chỉ không còn token.
  3. Giữ terminal mở. Ctrl+C dừng dashboard — các run và các autopilot do dashboard khởi chạy cũng dừng theo. Autopilot bật bằng agent-brain auto trong terminal khác thì vẫn chạy.

Terminal của serve cũng in các dòng Autopilot … của autopilot do dashboard bật.

Đặc điểm cần biết

  • Token mới mỗi lần khởi động, không ghi xuống đĩa. Khởi động lại serve thì cookie cũ hết hiệu lực — mở URL mới.
  • Chỉ một serve tại một thời điểm. Chạy cái thứ hai sẽ bị từ chối kèm PID và cổng của cái đang chạy.
  • Chỉ nghe 127.0.0.1: máy khác trong mạng LAN không vào được. Đây là chủ ý vì dashboard chạy được lệnh trên máy bạn.
  • Chạy offline hoàn toàn: CSS, JavaScript, font đều nằm trong binary.
Không chia sẻ URL có tokenAi có token đều điều khiển được agent trên các dự án của bạn. Không dán URL vào chat, issue, log hay ảnh chụp màn hình.

Bố cục chung

  • Thanh trên: các mục điều hướng (Tổng quan, Giao việc, Thống kê, Dự án; Chi tiết task mở từ thẻ task), bộ lọc profile (Tất cả / work / personal) và nút đổi giao diện sáng/tối.
  • Bộ lọc profile chỉ lọc những gì bạn thấy (task, thống kê, gợi ý dự án). Nó không đổi tài khoản chạy task.
  • Dữ liệu tự cập nhật (màn hình task mỗi 3 giây, Tổng quan mỗi 4 giây; log là trực tiếp). Mất kết nối thì hiện "Không cập nhật được — đang thử lại..." và tự kết nối lại.
  • Dùng được bằng bàn phím: Tab giữa các điều khiển, Escape đóng hộp thoại, focus quay về nút đã mở hộp thoại.
  • Nếu bấm một nút điều khiển trên dữ liệu đã cũ (task vừa đổi trạng thái), server từ chối và màn hình tự tải lại; xem lại rồi bấm lần nữa.

  • Task có autopilot đang chạy có thêm huy hiệu ◐ Autopilot sau ba ô Lead / Dev / QA.

7.2 Giao việc #/assign

  1. Yêu cầu (tiếng Việt): mô tả việc cần làm.
  2. Dự án: gõ tên, alias hoặc tên không dấu rồi chọn trong danh sách gợi ý (chuột, hoặc ↑/↓ rồi Enter). Dự án thiếu thư mục hiện mờ và không chọn được.
  3. Quy trình (mới, 5.2): danh sách chọn, mỗi dòng có tên, nhãn (mặc định của dự án, có sẵn, từ workflows.json, autopilot / chạy tay), dòng giai đoạn và dòng giới hạn, ví dụ plan ⇄ review → Bạn → code ⇄ review → QA ⇄ sửa / 3 vòng · 60 phút · $20. Mặc định chọn quy trình của dự án, không có thì mac-dinh. Đổi dự án sẽ chọn lại mặc định của dự án mới, trừ khi bạn đã tự chọn. Dòng dưới cho biết "Quy trình này tự chạy autopilot và luôn dừng ở bước bạn duyệt plan." hoặc "Quy trình này chạy tay: bạn bấm từng bước."
  4. Tên task (slug): tự tạo từ yêu cầu giống CLI; sửa được.
  5. Kiểm tra khung thông tin (dự án, nhánh hiện tại, profile) rồi bấm Giao việc. Quy trình autopilot chạy agent-brain auto --start; quy trình chạy tay chạy Lead.

Tên khớp nhiều dự án thì màn hình hiện "Tên khớp nhiều dự án — chọn một" và nút Giao việc bị khóa. Nút bị khóa luôn kèm lý do (dự án đang bận, đang chạy autopilot, đã có run personal…). workflows.json có lỗi thì hiện khung hổ phách "workflows.json có lỗi", hai quy trình có sẵn vẫn chọn được. Không tải được danh sách: "Không tải được danh sách quy trình. Task sẽ chạy bằng quy trình mặc định của dự án."

7.3 Chi tiết task #/task/N

Thứ tự từ trên xuống: thẻ tiêu đề → biểu ngữ dừng (chỉ khi autopilot dừng) → Pipeline → khung Vướng mắc / Cần sửa → Sổ lượt chạy → Kế hoạch (.plan.md) → Báo cáo QA → Log realtime.

Đầu thẻ Pipeline

  • Huy hiệu autopilot: Autopilot: tắt · Autopilot: đang chạy · Autopilot: đang dừng (chờ run hiện tại xong) · Autopilot: chờ bạn duyệt plan · Autopilot: chờ bạn · {lý do} · Autopilot: đã dừng (driver mất, ví dụ serve tắt giữa chừng — bấm Bật autopilot để chạy tiếp từ bước dở) · Autopilot: xong.
  • Nút Bật autopilot / Dừng autopilot cạnh huy hiệu. Dừng autopilot là dừng mềm: run hiện tại chạy nốt rồi autopilot không bắt đầu bước mới (muốn dừng ngay: Kill). Khi autopilot đang chờ ở cổng, Dừng autopilot tắt autopilot cho task: "Đã tắt autopilot cho task này — Duyệt plan giờ chỉ ghi nhận, không tự chạy tiếp. Bấm Bật autopilot để bật lại."
  • Dòng quy trình: Quy trình: mac-dinh · plan ⇄ review → Bạn → …. Task tạo trước 5.2: Quy trình: chưa có (task tạo trước Phase 5.2) — chạy tay từng bước.
  • Dòng ngân sách: Ngân sách: M / B phút · $X / $Y, thêm sắp hết (≥ 80 %) hoặc đã hết (≥ 100 %). Có ≈ trước số tiền khi gồm chi phí ước tính từ token của run bị dừng; khi đó số này có thể lớn hơn Tổng đến giờ ở Sổ lượt chạy.

Luồng pipeline vẽ theo bản sao quy trình của task: Bắt đầu → nhóm plan → Bạn → nhóm build → nhóm QA. Mỗi nhóm vòng lặp chứa hai thẻ xếp chồng và chân nhóm ⟲ vòng N / cap (hoặc chưa chạy; quy trình không có vòng lặp chỉ ghi ⟲ vòng N).

  • Lệnh git bạn thêm vào common_args (ví dụ git push) vẫn bị hook từ chối.

C. HTTP API của dashboard

Mọi route cần cookie phiên (trừ GET /?token=… dùng để lấy cookie). Lệnh ghi (POST/PUT) cần thân JSON và còn kiểm tra Origin và Content-Type; thân của route task có khóa lạ bị từ chối. Các nút điều khiển gửi rev của task đang hiển thị: rev cũ trả 409 ("kind": "stale"). Dành cho người phát triển; người dùng thường không cần gọi trực tiếp.
